## 주요 의사결정 5가지

### ① 컨셉 피봇 — 학부모 → 교사·교육청 도구
적대적 검증(38/100) 결과 받아들여 B2C 모델 폐기. **B2G(시도교육청 학습종합클리닉센터 연계)** 정조준.
- 이유: 학부모는 자녀 약점을 노출할 동기가 약함. 학생은 점수 입력 메타인지 없음. 시장 좁음.
- 변경: 홈페이지·기획서·프로덕트 톤 모두 교사 중심으로.

### ② 학술 방어선 보강
가드너 8지능 비판(Visser et al. 2006: 단일 g 요인 수렴) 인지하고:
- 가드너는 *내부 표상*으로만 유지
- 사용자 노출 표면은 **OECD 21세기 스킬 + Holland 흥미 코드** (`src/lib/oecd-mapping.ts`)
- 모든 점수에 ±1.5점 신뢰구간
- "1회 5분 탐색 결과 — 진단 아님" 면책 박스

### ③ 영재 의뢰서 자동 발송 폐기
원래 안: AI가 영재교육원 의뢰서 자동 생성·발송
변경 후: **교사 검토용 "추가 관찰 후보" 카드**로 톤다운. AI는 의뢰서 *초안*만 제공.

### ④ 다문화 가중치 폐기 → 신뢰도 페널티
원래: 다문화 학생에 언어지능 +0.5점 (알고리즘 공정성 비판 위험)
변경: **가중치 사용 안 함**. 다문화 변수는 *해석 신뢰도 페널티*("이 결과의 한국어 의존도가 높아 불확실성이 큼")로만.

### ⑤ 공공데이터 결합을 출력단 → 입력단으로 이동
원래: 진단 후 추천 단계에서 도서관정보나루 사용
변경: 학교 단위 또래 분포(NEIS·학교알리미)를 Claude 시스템 프롬프트에 *진단 시점*에 컨텍스트로 주입 → 학생 결과를 항상 *상대 위치*로 해석.

## 사용자 검토 포인트

다녀오신 후 다음 사항을 결정해주시면 다음 단계로 갑니다.

1. **컨셉 피봇 동의 여부** — "학부모 도구 → 교사·교육청 도구"로 가는 것에 동의하시나요?
2. **메시지 자극 회복** — 피봇 후 "와닿음"이 약해진 측면이 있습니다. 발표 시 강한 한 장면(시범 학교 부진학생 발견율 N → M%) 시뮬레이션 추가 의향?
3. **학술 프레임 선택** — 현재 OECD + Holland로 표면 변경. 더 단순하게 가려면 "탐색 카드"라고만 부르는 옵션도 있음.
4. **인증키 발급** — `npm run dev`로 mock 동작은 됩니다. 실 데이터 연동을 원하면 도서관정보나루·NEIS·학교알리미 키를 사용자가 발급해야 합니다 (즉시·무료).
5. **GitHub 공개 repo 게시** — 대회 출품 시 코드 공개 유리. 결정해주시면 push 가이드 드립니다.

## 솔직한 자기 평가

**잘된 것**:
- 적대적 검증을 받아들여 큰 피봇을 자율 결정 (사용자 부재 중)
- 코드 + 기획서 + 검증 문서가 정합성 있게 일관됨
- 학술적 방어선·정책 수용성·사회적 임팩트 세 축이 정렬

**아쉬운 것**:
- npm install 미완료 상태로 종료 (사용자가 직접 실행)
- 실 API 연동 테스트 미완료 (인증키 없음)
- 일부 페이지(/diagnose)는 Next 15 Suspense 패턴 적용했지만 실 빌드 검증 안 됨
- 시연 영상 미녹화

**위험**:
- 가드너 8지능을 *내부에서라도* 사용하는 것 자체가 비판받을 수 있음 → 사용자가 "탐색 카드"로 더 단순화할지 결정 필요
- B2G 진입은 1~2년 걸림 → 단기 매출 기대는 버려야 함을 사용자가 인지하셔야 함

이 모든 결정은 *되돌릴 수 있음*. 사용자 의견에 따라 자유롭게 다시 피봇 가능합니다.
