# 군포 독서·문화행사 데이터 — 수집 아키텍처 & 확장 계획

> 핏치(Pitch) · 군포 사회적경제 창업팀
> "전자동 크롤링은 환상, 전수동은 인건비 → **하이브리드(자동 수집 + 운영자 검수)**가 정답"

---

## 1. 현재 실연동 (PoC 검증 완료)

| 소스 | 방식 | 수집량 | 상태 |
|---|---|---|---|
| 군포 도서관 문화행사 | 공공데이터포털 OpenAPI | **591건** | ✅ LIVE |
| 군포 추천도서 | 공공데이터포털 OpenAPI | **156건** | ✅ LIVE |
| 도서관 인기검색어 | 공공데이터포털 OpenAPI | **1,932건** | ✅ LIVE |
| 도서관 공지사항 | 공공데이터포털 OpenAPI | **318건** | ✅ LIVE |
| 그림책꿈마루 문화행사 | 공공데이터포털 OpenAPI | 8건 | ✅ LIVE |
| 군포 도서관 장서(도서목록) | 공공데이터포털 파일 | **828,589권** | ✅ |
| **그림책꿈마루 (포스터+신청URL)** | **자동 스크래핑(Playwright)** | **12건** | ✅ LIVE |

- 공공 API는 **namespace 번호만 추가하면** 동일 코드(`datago.mjs`)로 전부 연동 — 명세서 불필요.
- 그림책꿈마루는 JS 렌더 사이트 → 헤드리스 브라우저로 **포스터 이미지 + 신청 URL**까지 수집.
- ⚠️ 공공 API는 **주기적 스냅샷**이라 실시간이 아님(예: 문화행사 최신 2025-11). 최신/임박 행사는 스크래핑·제휴로 보강 필요.

## 2. 3-Tier 하이브리드 수집 아키텍처

```
 [Tier 1] 공공 API 자동 동기화 ──┐
 [Tier 2] 자동 스크래핑/크롤링 ──┼─→ 정규화 → 중복제거 → 분류 → (운영자 검수) → 게시 → 개인 맞춤 추천
 [Tier 3] 알림 → 운영자 수동등록 ─┘
```

### Tier 1 — 공공 API 자동 동기화 (뼈대)
- **대상**: 공공데이터포털·경기데이터드림에 등록된 데이터셋
- **방식**: cron으로 주기 fetch → 정규화 저장
- **장점**: 가장 안정적, 유지보수 최소, 구조 보장
- **한계**: 스냅샷 주기 lag (실시간 아님)

### Tier 2 — 자동 스크래핑/크롤링 (API 없는 기관)
- **대상**: 군포문화재단, 군포 통합도서관 공지, 평생학습원, 그림책꿈마루 상세·포스터
- **방식**: cron 주기 수집 + 신규/변경 감지(diff)
- **장점**: 최신 데이터·포스터·신청링크 확보
- **한계**: 사이트 구조 변경 시 깨짐 → **모니터링·알림·robots/약관 준수 필수**

### Tier 3 — 알림 → 운영자 수동 등록 (하이브리드 핵심)
- **대상**: API·스크래핑 불가하거나 신뢰도가 중요한 행사(공유학교, 민간 독서모임 등)
- **방식**: 키워드/RSS 모니터링 → **신규 감지 시 운영자에게 알림** → 검수 후 직접 등록
- **장점**: 품질·정확도 보장, 누락 방지
- **한계**: 인건비 → 단, **군포 단일시 파일럿은 행사 수가 적어 수동 검수 충분히 감당**

## 3. 확장 계획 (단계별 로드맵)

| 단계 | 기간(예시) | 내용 | Tier |
|---|---|---|---|
| **Phase 1** | 현재(PoC) | 공공 API 6종 + 그림책꿈마루 스크래핑 실연동 | 1·2 |
| **Phase 2** | 1~2분기 | 자동 스크래핑 확장: 군포문화재단·도서관 공지·평생학습원 + 신규감지 알림 | 2 |
| **Phase 3** | 2~3분기 | 운영자 검수 워크플로우 구축(알림→등록), 공유학교 등 비정형 소스 편입 | 3 |
| **Phase 4** | 3~4분기 | **기관 제휴**: 군포시·도서관·문화재단과 공식 데이터 피드/관리자 연동 | 제휴 |

### 제휴(Phase 4)가 장기 최강수
- 스크래핑 리스크(구조 변경·차단) 제거 + 데이터 **독점성** 확보
- 공식 피드/admin 권한 → 실시간·정확·법적 안전
- **사회적경제 창업팀 자격**이 군포시·기관 제휴의 명분이 됨

## 4. 수집 → 개인화 연결 (제품 가치)

```
통합 행사 DB ─→ 각 행사 [신청 URL] ─→ 시민이 신청 ─→ 신청 내역이
                                              └→ 개인 "독서은하"(북 포트폴리오)로 누적
                                              └→ 독서 이력·관심 기반 다음 행사/도서 AI 추천
```
- 독서은하 = **학생 개인의 북 포트폴리오**(개인 자산). 지역 행사·인기도서·추천도서가 개인화 추천의 "시드".
- 신청·참여 데이터가 쌓일수록 개인 맞춤 추천 정교화 → **데이터 해자**.

---

## 5. 운영·리스크 관리
- **스크래핑 유지보수**: 셀렉터 변경 감지 + 실패 알림(0건 수집 시 경보)
- **법적**: robots.txt·이용약관 확인, 요청 간격(rate limit), User-Agent 명시, 공공데이터는 출처 표기
- **데이터 정직성**: 화면·피치에 `실연동 / 스크래핑 / 예정`을 라벨로 명시 (mock 금지)
