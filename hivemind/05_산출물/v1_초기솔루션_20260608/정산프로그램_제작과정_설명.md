# 정산 프로그램은 어떻게 만들어졌나 — 문제와 해결

> 유통사 28곳의 제각각인 정산서를, "작가에게 얼마를 왜 줘야 하는지"가 자동으로 나오는 하나의 표준 데이터로 만든 과정입니다.

---

## 0. 한눈에 보는 흐름

정산서 업로드 → **① 형식 통일** → **② 항목 통일** → **③ 작품·작가 자동 매칭** → **④ 미매칭 줄이기** → 작가별 정산·근거·통계·정산서 발행

각 단계에서 마주친 "진짜 문제"와 그걸 어떻게 뚫었는지를 아래에 적습니다.

---

## 1. 첫 번째 벽 — 파일이 파일이 아니었다 (형식 통일)

**문제**: 유통사마다 정산서 형식이 전부 달랐고, 심지어 거짓말을 했습니다.
- 확장자는 `.xls`인데 **실제로는 HTML 문서**인 파일이 16종 (네이버·노벨피아·무툰·밀리·하이북 등). 엑셀로 열면 보이지만 프로그램으론 안 읽힘.
- 북큐브·애니툰은 `.xlsx`인데 **내부가 깨진 비표준 파일**이라 일반 라이브러리가 오류.
- 로망띠끄·신영미디어·에피루스는 **글자 인코딩(cp949)이 달라** Mac에서 한글이 깨짐.
- 피플앤스토리는 **HTML 태그가 누락된 깨진 파일**, 리디는 **zip 압축**.

**해결**: 확장자를 믿지 않고 **파일 첫 바이트(매직바이트)로 진짜 형식을 판별**하게 했습니다. HTML이면 HTML로, 깨진 xlsx는 깨진 부분을 갈아끼우는 관용 로더로, cp949는 자동 감지해 복원. → **69개 파일 전부 한 가지 표준 표로 변환 성공.**

---

## 2. 두 번째 벽 — 같은 정보를 다른 이름으로 (항목 통일)

**문제**: "작가"를 어디는 `작가명`, 어디는 `저자`, 어디는 `글작가`라 부르고, "정산액"도 `정산금액`·`소득액`·`총지급액`·`공급대가`처럼 12가지로 제각각.

**해결**: 유통사 25종 각각의 **컬럼 이름을 표준 항목(작품명·작가·레이블·총매출·정산액·구분)으로 매핑**하는 규칙표를 만들었습니다. 위치가 아니라 **이름 기준**이라 양식이 살짝 바뀌어도 견딥니다.
- 합계행(`합계`·`SUM`·`Total`)은 제거하되, **그 합계로 우리 계산이 맞는지 자동 검증**(40개 파일 전수 일치)에 재활용.
- 정산액을 안 주는 유통사는 산식으로 계산(예: 네이버 = (합계−수수료)×0.7)하고, **"제공값/계산값"을 꼬리표로 붙여** 나중에 추적 가능하게.

---

## 3. 핵심 벽 — "월야환담 28권"과 "월야환담 29권"은 같은 작품인가? (자동 매칭)

이게 이 프로젝트의 진짜 어려움이었습니다. **같은 작품·같은 작가인데 유통사마다 표기가 다 달랐어요.**

### 3-1. 작품명 통일 — 정규화(normalize)

원문을 그대로 비교하면 **15.8%만 일치**했습니다. 그래서 표기 차이를 기계적으로 걷어냈습니다.

| 문제 표기 | 제거 규칙 | 결과 |
|---|---|---|
| `보스 오빠, 살살!` ↔ `보스오빠, 살살!` | **띄어쓰기 제거** | 같은 작품 |
| `21세기 대마법사 10`, `회귀의 전설 3부 1222화` | **권·화·부 번호 제거** | 21세기 대마법사 / 회귀의 전설 |
| `[e북]`, `[단행본]`, `(개정판)`, `*세트구매*` | **태그·괄호 제거** | 본 제목만 |
| `술탄(Sultan)`, `퇴마사(巫堂)` | **괄호 병기 제거** | 술탄 / 퇴마사 |
| `월야환담 28권 : 광월야`, `29권 : 광월야` | **제목 중간 권 번호까지 제거** | 둘 다 = 월야환담 광월야 |

→ 일치율 **15.8% → 65.6% → 78.8%**로 단계적으로 올렸습니다. (단, `월야환담` 본편 / `광월야` / `채월야`처럼 부제가 다르면 별개로 유지 — 무리하게 합치지 않음)

### 3-2. 작가명도 똑같이 — `[정천]` = `정천`

작가명도 `[정천]`과 `정천`, `이윤정(탠저린)`과 `이윤정 (탠저린)`이 다른 작가로 잡혔습니다. → **대괄호·공백을 제거해 통일**. 작가 수가 4,310 → 4,251명으로 정리(중복 59명 병합).

### 3-3. 누락된 작가를 다른 유통사에서 끌어오기 — 당월 상호대조

작가를 **안 주는 유통사**(무툰·문피아·예스24 등)가 많았습니다. 핵심 아이디어:
> "같은 작품을 작가까지 주는 다른 유통사가 있으면, 거기서 끌어와 채운다."

예: `월야환담`을 예스24는 작가 없이, 알라딘·노벨피아는 **홍정훈**으로 줌 → 알라딘 정보로 예스24 빈칸을 채워 **완전 매칭**.

여기에 **2022년 수작업 정리본(38,063행)을 초기 자산으로 승계** → 그동안의 수작업이 버려지지 않고 시스템 시드가 됨.

**결과: 작가·레이블 자동 완전매칭 98.1%.**

---

## 4. 마지막 벽 — 미매칭 %를 계속 낮추기

98%까지 왔어도 남은 미매칭을 단계적으로 더 줄였습니다.

| 조치 | 무엇을 했나 | 효과 |
|---|---|---|
| ① 번들 분리 | `원스토리 패스` 같은 구독 상품은 작품이 아니므로 분리 (단, '삼국지 싸이코**패스**' 같은 실제 작품 오인 방지 위해 정밀 패턴만) | 정산액 미매칭률 **0.42% → 0.20%** |
| ② 권 번호 통합 | `월야환담 28권/29권` 통합 → 한쪽에 있던 작가가 전체에 적용 | 미매칭 작품 **151 → 119** |
| ③ AI 제안 | 유사 작품·시리즈 형제작(광월야↔채월야)·오타(`바래`↔`바라`)에서 작가를 찾아 **신뢰도·근거와 함께 제안 → 승인** | 근거 있는 건 자동 제안 |
| ④ 알라딘 조회 | 단서가 전혀 없는 단독 유통작(예스24 등)은 **알라딘 도서 DB에서 작가·ISBN 조회** → 제안 | `신수의 주인`→태선, `습기`→마태 등 확보 |

**핵심 원칙**: AI·외부조회는 **근거 있는 것만 제안**하고, 단서 없는 건 추측하지 않고 담당자 승인으로 넘깁니다. 틀린 작가에게 정산되는 것을 막기 위해 **무엇도 자동 적용하지 않음.** 모든 승인·거절은 **히스토리로 기록**(감사 추적).

---

## 5. 그래서 지금 무엇이 되나
- 작가별 정산액 + **왜 그 금액인지**(어느 유통사·작품·산식) 근거 추적
- 작가별 **정산 명세서 발행**(원천징수·실지급액)
- 유통사별·작품별·통계(차트) 분석, 통합 검색
- 미매칭은 AI·알라딘 제안 → 승인으로 **계속 줄어드는 구조** (한 번 등록하면 이후 자동)

## 6. 미매칭 % 진행 요약 (한 줄)
원문 그대로 15.8% → 정규화 78.8% → 당월 상호대조·시드로 **완전매칭 98.1%** → 번들·권통합·AI·알라딘으로 **미매칭 정산액 0.2%대까지** 축소, 그리고 운영하며 계속 낮아짐.
