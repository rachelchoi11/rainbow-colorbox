# 정산서 파서 구현 버전 히스토리

> 대상: 하이브마인드 정산 표준화 솔루션(settlement-app)의 유통사 정산서 파서·산식
> 원칙: 유통사 정산서는 양식·명명·제공방식이 수시로 바뀌므로, 데이터가 추가될 때마다 파서를 확장하고 **1~4월 회귀검증(무변경)** 을 통과시킨 뒤 반영.

---

## 0. 파서 공통 구조
- **형식 판별**: 매직바이트로 실제 형식 판별 (HTML 위장 .xls, 깨진 xlsx, cp949 인코딩, zip 등 확장자와 무관하게 처리)
- **플랫폼 매칭**: 파일명 정규식 → 스펙 선택 (`find_spec`)
- **헤더 위치**: 고정행 `header=(a,b)` 또는 **`header_find`(토큰 자동탐지)**. 그룹 헤더는 `그룹/디테일`로 평탄화
- **컬럼 매핑**: 표준 필드(title·author·label·gross·settle·book_type…)에 **후보 컬럼명 리스트**를 이름 기준으로 매핑 (위치 불변 가정 안 함)
- **산식(calc)**: 매출·정산액 미제공 플랫폼은 `gross_calc`·`settle_calc`로 계산, `basis` 플래그로 제공값/계산값 구분
- **검증**: 플랫폼 자체 합계행과 대사 (±1원 PASS)

## 1. v1 — 초기 (2·3월) · 2026-06-10 · 스펙 30종
**데이터**: 유통사 28~29곳의 26년 2·3월 정산서 69파일 (본부장 최초 제공분).

**파서**:
- 유통사 25종 컬럼 → 표준 항목 매핑. HTML 위장 .xls 16종, 깨진 xlsx(북큐브·애니툰), cp949, zip(리디) 전부 처리 → 145,018행 표준화.

**산식(정산액/매출 미제공처 계산)**:
- 네이버시리즈: 정산액 = **(합계 − 마켓수수료추정) × 0.7**
- 미스터블루: 판매유형별(정액+종량) 정산액 **합산**
- 리디: 매출 = 판매액 + 취소액 / 조아라: 매출 = 단가 × 판매건수 / 블라이스: 정산액 = 판매액 × 0.7

**검증**: 40개 파일 합계행 전수 일치.

## 2. v2 — 고도화 (1~4월) · 개발 2026-06-19 / 배포 06-26 · 스펙 +7
**추가 데이터(본부장 제공)**: 1·4월 완전판 + 과거 '취합 불가'였던 **교보문고·모픽** + 에이블리 2·3월.

**파서 추가/수정**:
- **모픽·교보문고** 스펙 신규 (교보 = B2B 기관납품, ISBN·공급사 보유 → 매칭키 자산)
- 노벨피아 `(1)` detail 양식 매칭 추가
- 명명 변경 수용: 원스토어(←원스토리), 오망띠끄_연재 / 로망띠끄_전자책, 알라딘 B2B(도서명·정가합 양식)

**산식(2026-06-15 반영)**:
- **예스24**: 매출 = 총정산액 ÷ 0.7 (매출 미제공 → 역산)
- **판무림**: 정산액 = 판매금액 × 0.7 (행단위 정산액 미제공)
- E2 작가 정규화 강화 (한자·영문 병기 통합)

**검증**: 151파일 **431,296행**, 대사 **86 PASS·0 FAIL**, 완전매칭 99.5%.

## 3. v2.1 — 11~12월 (이번) · 2026-07-01 · 스펙 +7 → 37종
**추가 데이터(본부장 제공, 6/24~25)**: 25년 11~12월 정산서 163파일(정산서 샘플 3) + 일매출 트래킹 샘플 + 작가 정산서 샘플. 일부 플랫폼의 **양식·명명·제공방식이 변경**됨.

**파서 수정/추가**:

| 플랫폼 | 무엇이 바뀌었나 | 대응 |
|---|---|---|
| **예스24** | 1종 → **3종 신양식**(B2B 기관납품 / B2C 소매 / 연재). 파일명이 `B2B_List`·`B2C_List`·`SerialWorkStatisticsList` | 3종 스펙 신규 + 파일명 접두 매칭. **정산액 직접 제공 → ÷0.7 산식 폐기**(구양식은 폴백 유지) |
| **카카오페이지** | 구양식(헤더 6~7행)으로 1~4월(1~2행)과 상이 | `header=(1,2)` → **`header_find` 자동탐지**로 구·신 통합 처리 |
| **네이버시리즈·미스터블루** | ID/PW 변경 → 월정산서 대신 **일매출(일별)** 제공 | 일별 스펙 신규(파일명=YYYYMMDD / 작품별정산_YYYY-MM-DD). 정산액 직접 제공, 월 집계 전제 |
| **로망띠끄** | 명명 `(로망띠끄 N월 1/2)`로 변경 | 매칭 확장(1=단행본/전자책, 2=연재). 컬럼은 기존과 동일 |
| **노벨피아** | 일별 판매형(상품명·판매합계·정산금액·연재단행) | detail 매칭에 `일별` 포함(월별 조회수형은 정산금 0으로 기존 유지) |

**검증**: 11~12월 **163/163 파싱**, 대사 **31 PASS·0 FAIL** / 1~4월 **회귀 431,296행·86 PASS 불변**(무회귀).

- 스펙 **37종** / 유통사 31곳+ / 1~4월 431,296행(86 PASS) + 11~12월 163파일(31 PASS).
- **교훈**: 유통사 정산서는 양식·명명·제공방식이 수시로 바뀐다. 파서는 ①파일명 정규식 매칭 ②헤더 자동탐지 ③이름 기준 컬럼 매핑 ④합계행 대사 4중 구조로 변화에 견디게 설계. 매 데이터 수령 시 **회귀검증(1~4월 불변) 필수**.
