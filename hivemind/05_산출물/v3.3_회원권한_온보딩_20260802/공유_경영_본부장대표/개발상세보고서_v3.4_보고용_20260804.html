개요

배포본(v2)은 정산 데이터를 분석하는 도구였음. 개발본(v3)은 이를 출판사 단위 멀티테넌트 서비스로 전환하고, 계약 체계·정산 마감·회원/권한·데이터 격리·영속 저장소를 갖춰 Railway 영속 볼륨으로 정식 배포했음.

1. 서비스화 · 데이터 계층

  • 정산 데이터에서 파생하던 출판사·계약·유통사를 영속 마스터로 분리, 정산은 그 위에 얹는 구조로 재설계.
  • 정산 매칭 엔진(core)은 무변경 → 회귀 불변식 유지. 운영자 콘솔 ↔ 출판사 워크스페이스 역할별 IA.
  • 출판사↔레이블 계층 확립: 통합 매핑표 458 레이블 → 158 출판사, 테넌트 843 → 128곳 정리(에피루스 등 파서 교정 포함).

2. 저장소 — SQLite

  • 마스터(출판사·계약·회원·초대·플래그·별칭 등)를 SQLite(WAL)로 이전. 최초 기동 시 기존 JSON 1회 자동 이관, 호출부 무변경.
  • 재시작·동시 쓰기·크래시에도 데이터 보존. 검증: 이관(출판사 128 등)·라운드트립·회귀 유지.

3. 계약 체계

계약마다 고유번호를 부여해 번호만으로 출판사·원작·매체·권리·형태가 읽힘.

0001 - AA001 - N - 1 - 00 └ 출판사 · 콘텐츠 고유번호 · 웹소설(N)/웹툰(T) · 계약유형 · 콘텐츠유형
  • 상태(초안/확정/종료): 소급 일괄=초안, 초안은 예상 지급액 미반영 → 확정 후 반영.
  • 유효기간(시작/종료월): 해당 기간 정산행에만 배분율 적용(과거 소급 방지).
  • 소급 일괄 등록: 정산 데이터의 작품·작가를 계약 초안 소스로 재활용해 일괄 생성.

4. 정산 산식 · 마감/원장

작가 지급 = 유통사 제공 정산액 × 계약 배분율 − 선인세(MG) − 원천징수. (유통사 제공값 기준.)

  • 유통대행 3계층(작가–출판사–관리자): 지급 대상이 출판사면 매칭 키를 출판사명(산하 레이블 합산)으로 전환, 계산식은 동일.
  • 정산 마감: 월 지급액을 확정=불변 스냅샷으로 고정(초안→확정→지급), MG는 이월 원장으로 이중 차감 방지.
  • 명세서(작가 지급)를 확정 계약의 배분율·MG·세율로 통일 → 계약관리 예상지급액과 일치.
검증 — 런1 MG 5천만 상계 → 지급 21,990,569 / 확정 후 런2 MG 이월(상계 0) → 70,340,569 (이중 차감 없음)

5. 회원 · 권한 · 접속 게이트 분리

조직역할요지
운영사최고관리자 / 운영자 / 뷰어전 기능·승인 / 운영·계정발급 / 조회
계약사출판사관리자 / 담당자자사 계약·정산 관리·사용자 관리 / 자사 조회
  • 접속 게이트 분리: 운영사=회원가입 후 승인 / 계약사=초대 링크 발급(초대는 계약사 전용).
  • 최초 접속: 동의 → 담당자 정보 입력(온보딩) → 워크스페이스. 계약사 화면은 계약사명이 주 브랜드.
  • 계약사 자체 관리: 출판사관리자가 자사 계약·정산 마감을 직접 관리(담당자는 조회 전용).

6. 보안 — 서버측 테넌트 격리

정산 조회·내보내기·명세서를 로그인 사용자의 테넌트 레이블로 서버측 강제. 계약·유통사·첨부·정산 마감은 소속 테넌트 검사(타사 403). 계약·마감 쓰기 지점 전부에 자사 스코프 강제.

7. 분석 · 운영 자동화 · 홈 재편

  • 성과 분석: 월별 추세·전월 대비·유통사 성과·상위 작가/작품·집중도·유통대행 비중.
  • 운영 자동화: 수집 현황판(유통사 31곳×월)·이상 탐지(급변·누락·음수·합계 불일치)·마감 스케줄러(마감일·리마인더).
  • 회사 정보 자가 관리(사업자·대표자·주소·입금계좌·세금계산서 이메일)·회원/출판사 삭제.
  • 운영자 콘솔 홈 재편: 고객사(출판사)별 정산 1차 블록, 유통사별 2차.

8. 정식 배포 — Railway 영속 볼륨

  • 상태(SQLite·세션·계약 첨부)를 영속 볼륨에 저장 → 재배포에도 계정·데이터 보존.
  • 환경변수 분리(세션 시크릿·DB 경로·첨부 경로·API 키), 시크릿 코드·저장소 미포함.
  • 최초 시드: 운영사 최고관리자 · 정산 1~4월(431,296행) · 출판사 128곳 · 계약사 데모 1곳. 재배포 후 데이터·세션 유지 확인.

개발본은 로그인·권한·온보딩·데이터 격리·계약 신뢰성·정산 마감·계약사 자체 관리·영속 저장소를 갖추고 Railway 영속 볼륨으로 정식 배포된 상태로, 외부 계약사 계정 운영이 가능한 최소 안전선을 통과했음.
