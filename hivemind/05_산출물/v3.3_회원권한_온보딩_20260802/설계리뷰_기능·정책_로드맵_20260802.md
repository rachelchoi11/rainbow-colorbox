## 0. 최우선 요약 (먼저 읽기)

**🔴 서버측 테넌트 데이터 격리가 없음 — 외부 계약사에 로그인 주기 전 반드시 해결.**
현재 RBAC(권한 검사)는 회원/초대/마스터 쓰기 엔드포인트에만 걸려 있고, **정산 조회·내보내기·업로드·매칭 등 대부분의 API는 "로그인+활성"만 확인**함. 스코프(어느 출판사 데이터인지)는 클라이언트가 넘기는 값에 의존 → 계약사 담당자가 요청 파라미터만 바꾸면 **다른 출판사의 매출·계약·지급처(계좌)·정산서까지 열람/다운로드 가능.** 데모(내부)는 괜찮지만, 실제 계약사 계정 배포 전 차단 필수.

| S4 | 🟠 | **가입 시 최고관리자 자가지정** — 승인 시 요청역할 유지, 드롭다운 미변경 승인하면 슈퍼권한 부여 | 가입 폼에서 역할 제거(기본 고정), 승인 시 명시 지정 |
| S5 | 🟠 | **users.json 손상/공백 시 부트스트랩 재개방** — 파싱 실패=회원0 취급 → 다음 접속자가 최고관리자 | 부트스트랩 조건 강화(파일 존재+파싱성공 구분), 파일 락 |
| S6 | 🟠 | **초대 토큰 만료 미작동** — INVITE_TTL_DAYS 정의만 되고 미사용, 링크 무기한 유효 | 만료 검사 구현 |

| S8 | 🟡 | 동의·온보딩 게이트가 클라이언트 전용(서버 미강제) | 서버에서 미동의 시 API 차단 |

| S10 | ⚪ | 쿠키 Secure 미설정, 이메일 서버검증 없음, 세션 고정 | https_only, 이메일 검증 |

### A-2. 정산·계약 리뷰 결과
회귀 불변식(431,296/99.50%/86)은 전부 무관(계약/테넌트 read-side·CRUD라 정산 계산 미접촉).
| # | 심각도 | 내용 | 조치 |
| --- | --- | --- | --- |
| C1 | 🟠 | **작품범위 부분일치 과매칭** — `str.contains`라 "달빛" 계약이 "달빛조각사"까지 흡수 → base·payout 부풀림. 소급 일괄이 정확 제목을 저장해도 접두어 겹치면 이중 스코프 | 정확 제목(work_key) 매칭으로 전환 |
| C2 | 🟠 | **명세서 PDF ↔ 계약 payout 불일치** — 고객 명세서는 배분율/MG/세율 무시하고 0.033 하드코딩+별도 rate 사용. 같은 작가인데 값이 다름 | 계약 기반 산식으로 단일화(권위 소스 확정) |
| C3 | 🟠 | **MG 상계가 로드 기간 의존·미회수분 소실** — 단월 로드 시 이중 차감, 초과 MG carry-forward 없음, 기회수 원장 없음 | MG 회수 원장(누적) 도입 (정책 3.3와 연동) |
| C4 | 🟠 | **content_no 파생 공유 안 됨** — 파생계약도 새 번호 제안, 전체 계약번호 유일성 검사 없음(동일 번호 2건 가능) | 파생=원작번호 재사용 UX + 유일성 경고 |
| C5 | 🟠 | **계약 첨부 IDOR** — 첨부 조회/다운로드에 권한·소유 검사 없음(경로검사만). 타 테넌트 첨부 id 넣으면 다운로드 | 소유 테넌트 검사 추가 |
| C6 | 🟡 | agency payee 원문 매칭(정규화 안 함)·중복경고 네임스페이스 비대칭 → 표기 다르면 0매칭 or 경고 회피 | 정규화 일치로 통일 |
| C7 | 🟡 | label→출판사 소스 2개(tenant.labels vs map.json) 불일치 가능; 중복 레이블 first-wins 무경고 | 단일 진실원천 + 충돌 표면화 |
| C8 | ⚪ | delete_contract가 첨부파일 미삭제(고아), pub_code 최고값 테넌트 삭제 시 재발급 충돌 가능 | 첨부 정리 + pub_code 영구할당 |

> 리뷰가 반증한 비이슈(정상): 소급 일괄 생성은 O(n) (O(n²) 아님), publisher_resolver는 payout당 1회 생성(계약마다 아님).

## B. 신규 기능 (제품이 실제로 필요)

- 🔴 **서버측 테넌트 격리 + 엔드포인트 권한 가드**(A-1 S1·S2)
- 🟡 **비밀번호 재설정**(분실 시 복구 수단 전무 — 현재 JSON 수기 편집만 가능)
- 🟡 **초대 이메일 실제 발송**(현재 링크 수기 전달) + **초대 취소/재발송/만료**
- 🟡 **본인 비밀번호 변경**
- 🟡 **테넌트 비활성화 시 소속 사용자 연쇄 정지**
- 🟡 **감사 로그**(로그인·승인·권한변경·초대·정지 이력 — 현재 권한변경만 부분 기록)
- ⚪ 계정 삭제/파기, 세션 일괄 로그아웃, 이메일 인증, 로그인 실패 잠금

**정산·계약**
- 🔴 **계약 유효기간(시작/종료일)** — 현재 서명 시점과 무관하게 전 기간 소급 적용. 과거 정산·중도 요율변경 정확도에 필수
- 🔴 **계약 상태 라이프사이클(초안/확정/종료)** — 소급 일괄 "초안"이 즉시 payout에 반영됨. 확정 게이트 없이는 미검토 70% 기본값이 예상지급 부풀림
- 🔴 **content_no ↔ 정산 작품 연결** — 지금 넘버링은 장식적. 실제 작품 id에 바인딩 필요
- 🟡 **계약 검색/필터/정렬 + 계약 마스터 내보내기**(현재 정산만 내보냄)
- 🟡 **테넌트 비활성화 연쇄(계약·유통사·payout·계정) + 테넌트 삭제 경로**

## D. 정해야 하는 정책 (PO 결정)

1. **가입 시 역할 자가지정 허용 여부** — 권고: 불가(기본 뷰어/운영자 고정), 최고관리자만 승격
2. **운영사 계정 생성 경로 단일화** — 초대 vs 가입승인 중 택1, 운영자의 운영사 초대 허용 여부
3. **초대 만료 기간** — 현재 14일 정의만. 확정·구현
4. **비밀번호 규칙** — 최소 길이/복잡도/재사용. (현 UI "8자"와 코드 minlength=6 불일치도 정리)
5. **뷰어·운영자의 테넌트 열람 범위** — 전 테넌트 vs 제한
6. **한 테넌트의 출판사관리자 복수 허용 여부·상한**
7. **테넌트 비활성화 시 사용자 처리**(연쇄 정지 vs 유지)
8. **약관 버전 변경 시 재동의 트리거** — 현재 버전 비교 안 함. 운영사도 동의 대상인지
9. **마지막 최고관리자 보호·자기정지 방지 규칙**
10. **약관·개인정보 처리방침 본문 소유·버전 관리 주체**

**정산·계약 정책**
11. **content_no 부여 방식** — 자동 연번 vs 작품 정체성(파생 공유)에 바인딩. 누가 부여하나
12. **초안 vs 확정** — 소급 일괄 초안이 즉시 예상지급에 반영되나, 확정 단계 후 반영하나
13. **MG 회수 모델** — 단월 상계(현재) vs 다월 누적 carry-forward. 큰 MG 작가 지급액에 큰 영향
14. **원천징수 3.3% + 산식 단일화** — /api/contracts payout과 명세서 PDF가 불일치(C2). 어느 쪽이 권위인지
15. **payee=출판사 base의 중복 레이블 tie-break** — 현재 first-wins 무경고
16. **유통대행사 스코프 정의** — 유통대행사 tenant.labels = 자사 레이블 vs 대행하는 전 출판사 레이블

## E-0. 실행 현황 (2026-08-02 착수)

**✅ Phase 1 완료 — 서버측 테넌트 격리 + 엔드포인트 권한 가드 (S1·S2·C5)**
- 정산 조회/내보내기/명세서를 로그인 사용자의 테넌트 레이블로 **서버측 강제**(클라이언트 스코프 무시). 계약사가 label 파라미터로 타사 레이블 넣어도 교집합으로 차단.
- 계약 조회·유통사·첨부는 소속 테넌트 검사(타사 403). 계약 첨부 다운로드 IDOR 차단.
- 전역 매칭/연구소 변경 POST는 lab:manage(운영자) 전용 미들웨어 가드.
- 업로드/샘플로드/유통사설정 권한 가드.
- **실측**: 같은 세션이라도 계약사=자사(6억)만·운영자=전체(12억), 타사 계약/유통사 403, 매칭변경 403, 라벨인젝션 0. 회귀 불변식 유지(431,296/99.50%/86).

**✅ 안전 수정 배치 완료 (정책 불필요)**
- S6 초대 만료(14일) 구현 · S7 비밀번호 최소 8자 서버검증 · S9 상태값 검증 + 마지막 최고관리자 정지 방지
- C8 계약 삭제 시 첨부 디렉터리 정리 · 배분율/세율 0~100% clamp · 배분율 0 저장 경고

**✅ Phase 2 완료 — 계약 신뢰성 (정책 11~14 결정: 전부 권장안 채택)**
- **초안/확정/종료 상태**: 계약에 state 추가. 소급 일괄=초안, 수동=확정. **초안은 예상 지급액 미반영**(counted=false, 목록에 "초안·미반영" 표시). 확정 후 반영.
- **유효기간(시작/종료월)**: 계약에 start/end. payout이 해당 기간 정산행만 배분(과거 소급 방지). 비우면 전 기간.
- **MG 누적 회수·잔액**: payout이 로드 기간 누적에서 회수, **미회수분(mg_remaining) 표시**(이월 대상). 목록에 "MG잔" 노출. (교차-업로드 영구 원장=정산 마감 기능으로 후속)
- **명세서 산식 통일**: 명세서 PDF가 이제 그 작가의 **확정 계약**의 배분율·선인세·원천징수 사용 → 계약관리 예상지급액과 일치(0.033 하드코딩·별도 요율 제거).
- 유닛 검증: 초안 미반영·유효기간 필터·MG 잔액 전부 통과. 회귀 431,296/99.50%/86 유지.

**✅ Phase 3 완료 — 회원 운영**
