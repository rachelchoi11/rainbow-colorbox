## 0. 한 줄 결론
RBAC·테넌트 격리·계약 모델은 실동작 확인됨. 그러나 **① 데이터가 재시작마다 소멸(영속성) ② 정산이 영구 '예상'(마감·원장 없음) ③ 계약사가 로그인해도 "내 돈"이 안 보임(세션 의존)** — 이 셋이 정식 서비스의 실질 벽. 보안 구멍 몇 개는 이번에 즉시 막음.

## 1-B. ✅ B2 + B3 구현 완료 (2026-08-02, "단일 최우선 투자")

- **B2 SQLite(WAL) 이전**: `db.py` 문서-블롭 저장소. tenants·contracts·users·invites·flags·splits·aliases·dist_cfg·tenant_dist를 SQLite로. 기존 JSON은 최초 기동 시 1회 자동 이관. load/save 시그니처 유지(호출부 무변경). **원자적 커밋·durable·재시작 생존**(파일 손상→빈데이터 disaster 제거). 이관 검증(tenants 128·users 2 등) + 회귀 유지.
- **B3 정산 마감/원장**: `settlement_run`(초안→확정→지급) + 라인 **불변 스냅샷**(확정 시 금액 고정, 재계산 아님) + **MG 이월 원장**(이전 확정 런 회수액을 승계해 이중 차감 방지). API(runs create/confirm/get/delete) + UI(정산 마감 화면·라인 상세·확정/지급). 검증: 런1 MG 5천만 상계→지급 21,990,569 / 확정 후 런2 MG 상계 0→지급 70,340,569(원장 정상).
- ⏭ 남은 B계열: B1(Railway 볼륨 — 인프라 설정), B4(세션 영속), B5(레이트리밋).

## 2. 🔴 런칭 블로커 (외부 정식 오픈 전 필수)

### B1. 데이터 영속성 — 재시작 시 전멸 (아키텍처 N1) · 효과 L
- 마스터 전부 gitignore + Railway 볼륨 미설정 → 재배포마다 테넌트·계약·계정·감사로그 소멸.
- **조치(단계)**: (즉시) Railway 볼륨 `data/` 마운트 + SESSION_SECRET env 고정 → 수 시간. (근본) 아래 B2.

### B2. JSON → 트랜잭션 저장소 (SQLite+WAL) (N2) · L
- 동시 쓰기 clobber 실측됨(파일럿 중 contracts 4→0 소멸). 원자적 쓰기로 1차 방어했으나 잠금·트랜잭션은 없음.
- **조치**: SQLite(WAL) 이전. 순서 users/invites/audit → tenants/contracts → aliases/splits/flags. `db.py` 심(shim)으로 load/save 시그니처 유지해 호출부 최소 변경.

### B3. 정산 마감/원장/지급 (N3) · L
- 모든 지급액이 인메모리 실시간 '예상'. 마감·불변 스냅샷·지급 상태·세금계산서 없음. MG 이월도 매번 재계산.
- **조치(최소 모델)**: `settlement_run`(테넌트·월·상태 초안→확정→지급) + `settlement_line`(마감 시 불변 스냅샷) + `payment`(지급 상태). 명세서는 스냅샷을 렌더. MG 잔액은 직전 확정 run에서 이월.

### B4. 인메모리 세션 한계 (N4) · M
- MAX_SESSIONS=3, 세션당 43만행. 4명째 축출, 멀티워커 불가. 계약사 파일럿: "로그인해도 내 정산 안 보임"의 직접 원인.
- **조치**: 업로드 파싱결과를 디스크(Parquet)로 영속 + 프로세스 공용 LRU 캐시. 마감(B3) 후엔 기간별 집계 테이블로 핫 엔드포인트가 43만행 미접근.

### B5. 로그인 레이트리밋/잠금 (N5) · S
- 무제한 시도 가능. 조치: IP+계정 시도 제한·N회 실패 잠금.

## 3. 🟡 런칭 직후 (제품 완성도)

### P1. 계약사 "내 돈" 대시보드 + 출판사 마진 지표 · M
- 계약사 파일럿 최우선 요구. 로그인 즉시 테넌트별 영속 정산 + **출판사 몫(정산액 − 작가지급 합계)·이번 달 작가 지급 총액·실수령**. 현재 "정산액"만 있고 마진 개념 자체가 엔진에 없음. (B3/B4 의존)

### P2. 회사 프로필/정산 계좌 · M
- 온보딩이 담당자 이름·연락처뿐. **사업자등록번호·대표자·주소·정산 입금계좌·세금계산서 이메일** 수집 필요(정산 SaaS 필수). `org:manage_own` 권한은 정의됐으나 이를 쓰는 엔드포인트가 없음(죽은 권한) → 자사 프로필 편집 API 실동작화.

### P3. 일괄 작업 · M (운영자 파일럿 2순위)
- 회원 일괄승인(✅ 부분: UI 일괄승인 있음, 서버 bulk 엔드포인트 없음)·계약 **일괄 확정/일괄 배분율**·초대 일괄발급. 소급 대량 계약의 핵심 병목.

### P4. 페이지네이션·서버검색·전 테넌트 계약뷰 · M
- 테넌트·회원·계약·감사 전량 반환. 128 테넌트·수백 계약에서 프런트 부담. q·limit·offset·status 필터 + 전 테넌트 계약 통합 검색.

### P5. 삭제/오프보딩 API · S
- 테넌트·회원·계약 삭제 없음(정지만). 잘못 만든 것 영구 잔존(파일럿도 수동 정리). 삭제/익명화 + 테넌트 전체 내보내기(개인정보 대응).

### P6. 감사 커버리지 확대 · S
- 현재 인증/회원/초대만. **테넌트·계약·유통사율 변경**은 중앙 감사에 없음(레코드 history만). audit에 편입 + 조회 필터.

### P7. SMTP 이메일 발송 · S
- 초대·비번재설정·마감알림. 자격증명 필요.

### P8. 계약번호 단건 일관성·suggest 상한 · S
- 단건 생성 시 넘버링 미입력이면 contract_no 공백(벌크는 자동) → 미완성 경고 또는 자동부여. suggest 500 상한 → 페이지네이션.

### P9. verify "합계행 없음" 65건 대체검증 · M
- 원본에 합계행 없어 43% 무검증 통과. 교차 유통사 대사 등 대체 검증 설계.
