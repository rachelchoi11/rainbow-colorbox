1. 개요

정산 표준화 솔루션을 초기 버전(v1)에서 고도화 버전(v2)으로 고도화 진행.

첫째, 데이터 처리 범위 확대. 과거 자동 취합이 불가능했던 교보문고·모픽을 자동화에 편입. 대상 기간을 2개월(2·3월)에서 4개월(1~4월)로 확장. 처리 규모 145,018행에서 431,296행으로 약 3배 증가.

둘째, 매칭 정확도 향상. 작가·작품 식별 규칙 정교화. 동일 기간 기준 완전매칭률 98.1%에서 98.6%로, 4개월 전체 기준 99.5%로 상향. 미매칭 정산액 비중 0.2%대에서 0.08%로 하락.

셋째, 매칭 오류 개선 연구 체계(연구소) 구축. 본 보고서의 중심. 매칭 규칙이 틀릴 수 있는 경로를 체계적으로 수집·진단하고 규칙에 반영하는 상시 개선 절차 마련. 실데이터에서 동명이작(同名異作) 오류를 발견한 것을 계기로 오류 유형 분류 체계·신고 기능·자동 탐지기·검토 절차를 갖추고 첫 개선 주기 완료.

2. 추진 배경

초기 버전은 유통사 28곳의 상이한 정산서를 작가별 정산 근거가 자동 산출되는 표준 데이터로 변환하는 목표를 2·3월 데이터로 달성한 검증된 최소기능제품(MVP). 다만 다음 세 가지 한계 존재.

  • 수동 처리 영역 잔존. 교보문고·모픽 등 일부 플랫폼은 자동 수집 범위 밖으로 분류되어 수동 처리 대상.
  • 단기간 검증. 2개월 데이터만으로는 양식 변동·신작 유입에 대한 강건성 미검증.
  • 정확도 개선의 비체계성. 매칭 오류를 발견할 때마다 개별 대응하는 구조 — 어느 지점이 얼마나 틀리는지 전체 지도 부재.

1·4월과 교보·모픽·에이블리 신규 데이터 확보 및 고도화 진행.

3. 매칭 정확도 개선 연구 체계 (연구소)

3.1 문제 인식 — 동명이작 발견

작품별 정산 화면 검토 중 "부장님 왜 이러세요" 항목에서 한 작품에 작가·출판사가 각각 둘씩 표시되는 이상 확인. 원본 추적 결과 서로 다른 두 작품이 하나로 병합된 상태.

실제 작품작가 / 출판사정산액유통 플랫폼
부장님 왜 이러세요 [개정판]주황연 / 리체북스앤미디어약 975,000원원스토리·예스24·알라딘 등 8곳
부장님, 왜 이러세요?창작집단 뻘 / BOOK 19약 750원미스터블루·원스토리

원인은 작품 식별 키가 제목의 구두점(쉼표·물음표)과 띄어쓰기를 제거하기 때문. 그 결과 "부장님 왜 이러세요"와 "부장님, 왜 이러세요?"가 동일한 키로 충돌·병합.

단순 결함이 아니라 매칭 규칙의 구조적 균형 문제. 구두점을 보존하면 동명이작은 분리되나, 같은 작품의 띄어쓰기 변형이 과도하게 분리되는 더 큰 부작용 발생. 따라서 규칙 완화가 아니라 틀릴 수 있는 모든 경로를 관리하는 체계 도입으로 판단.

3.2 연구소의 정의

연구소는 결과값 신고와 자동 탐지로 의심 사례를 모으고, 검토·진단을 거쳐 규칙에 반영한 뒤 효과를 재측정하는 순환 절차.

신고 또는 자동 탐지 → 수집(상태 관리: 열림 / 검토중 / 규칙반영 / 기각) → 진단 및 규칙 반영 → 재측정으로 효과 검증 → (반복)

데이터 처리 신뢰의 본질은 한 번 정확한 결과가 아니라 틀린 부분을 신속히 찾아 고치고 재발을 막는 능력. 연구소는 이 능력을 시스템에 내장.

3.4 첫 개선 주기 — 작가 정규화 강화(E2)

연구소가 적출한 첫 과제. 작가가 둘 이상으로 잡힌 의심 사례 489건 분석 결과, 대부분이 실제 동명이작이 아니라 같은 작가의 표기 변형임을 측정으로 확인. 예: 한자 병기(필환 / 필환(筆煥)), 붙은 한자(무영 / 무영武映), 구두점·영문 병기(로체니콥 / 로체니콥. / 로체니콥(rocheni-cob)).

이에 작가 정규화 규칙을 강화하여 한글 이름에 붙은 한자·영문 병기와 구두점 통합. 동시에 오통합 방지 안전장치 적용 — 필명(이윤정(탠저린)), 공동작가 표기(사마달, 고월), 순수 영문 이름(Magoing)은 보존. 단위 테스트 10건(통합 7 / 별개유지 3) 전수 통과.

4. 주요 개선 사항

4.1 데이터 처리 범위 확대

신규 플랫폼 편입(교보문고·모픽). 과거 자동 취합 불가였던 두 플랫폼을 파서에 정식 등록. 모픽은 작가·출판사·매출·정산액을 모두 제공하며 유통대행 신호(제공사=스토린랩) 포함. 교보문고는 기관 납품형으로 한 도서가 납품처별 다중 행으로 나뉘어 합산 처리 필요, ISBN 보유로 향후 작품 식별의 정밀 키로 활용 가능. 교보문고는 원본 합계와 자동 대사 결과 정확히 일치(1월 2,155,698원, 4월 3,035,099원).

대상 기간 확장(2개월에서 4개월). 1·4월 추가. 다중 소스 통합 시 중복 파일 제거로 정산액 이중 계상 차단.

신규 월 양식 변동 대응(67,400행 복구). 신규 월에서 파일 명명·양식이 바뀐 사례 발견·수정. 기존 규칙이었다면 누락되었을 데이터.

4.3 유통대행 모드 기반 마련

솔루션을 유통대행(공급자) 사업의 기반으로 삼는 방향을 데이터 구조에 반영. 측정 결과 기존 가정과 달리 실데이터에 출판사 정보가 상당 부분 존재(고유 출판사 946종, 식별률 99.5%, 미상 1.17%). 표준 스키마에 제공사·유통대행 여부 필드 추가, 스토린랩이 각 출판사에 정산할 금액을 집계하는 출판사별 정산 뷰 신설(상위: 매드햇 3.57억원, 도서출판 청어람 1.06억원 등).

4.4 미매칭 보드 운영 기능

AI 제안·외부 도서 DB 조회 결과에 전체선택·선택승인·전체승인 추가. 결정 이력에서 복원(되돌리기) 기능과 사유 입력, 전체선택 복원 지원. 복원 시 등록 이전 매칭 상태로 환원, 모든 행위는 감사 추적 기록으로 보존.
