# M2 — 유통대행 vs 솔루션-only 모드 분리 (설계 노트 v1)

- 작성일: 2026-06-19 | 상태: 측정 기반 초안
- 전제: 솔루션은 미끼, **유통대행(공급자) 자리**가 진짜 목표 (책↔출판사 정산이 핵심)

## 1. 측정으로 드러난 사실 (메모리 가정 정정)

기존 가정("유통대행 책은 raw에 출판사 정보가 없다")은 **실데이터(1~4월)로 과한 것으로 확인**:

| 측정 | 값 |
|---|---|
| 고유 출판사(레이블) | **677종** (매드햇·시계토끼·도서출판 청어람·뿔미디어…) |
| `스토린랩`이 레이블로 등장 | **27행뿐** → raw 출판사는 진짜 출판사명 |
| 레이블 0% 플랫폼 | 8곳 (문피아·무툰·블라이스·예스24·올툰·조아라·큐툰·피플앤스토리) |
| 위 8곳 교차참조 보강률 | 50~82% (피플앤스토리만 12%) |
| **출판사 끝내 미상** | **1.17%** |
| 유통대행 명시신호 | 모픽 `제공사`=스토린랩(100%), 알라딘B2B `공급사`=스토린랩 |

→ **출판사별 정산 그룹핑은 이미 실데이터로 가능.** 책↔출판사 마스터는 8곳 보강 + 1.17% 잔여 처리용으로 여전히 필요.

## 2. 두 모드 정의

| | 모드1 — 유통대행 (우리=공급자) | 모드2 — 솔루션-only |
|---|---|---|
| 주체 | 스토린랩이 출판사들 책을 플랫폼에 공급 | 출판사가 자기 플랫폼 계정으로 직접 |
| 데이터 흐름 | 플랫폼→스토린랩→**출판사**→작가 | 플랫폼→출판사(본인) |
| 핵심 뷰 | **출판사별 정산**(스토린랩이 각 출판사에 얼마) + 작가별 | 작가별 정산 |
| 출판사 정보 | 우리가 마스터로 관리(raw 보강) | 본인 데이터라 자명 |
| 격리 | 스토린랩이 전체 열람 | 본인 데이터만 (테넌트 격리) |

> 모드 분리의 **데이터 측면** = 출판사 마스터 + 출판사별 집계(M2, 본 작업). **접근통제 측면** = 멀티테넌트(M3 운영화)와 연결.

## 3. 데이터 모델 (M2 구현 범위)

- **schema v2 추가 필드** (구현완료): `supplier`(제공사/공급사), `is_distribution`(=스토린랩 공급 여부)
- **책↔출판사 마스터**: `title_norm → 출판사(레이블)` (현재 engine 교차참조로 자동 구축, 1.17% 잔여는 미매칭 큐)
- **출판사별 정산 집계** (구현완료): 출판사별 정산액·작품수·작가수 → 통합본 `출판사별정산` 시트

## 4. 남은 설계 결정 (사용자 확인 필요)

1. **모드2(솔루션-only) 우선순위** — 현재 데이터는 전부 스토린랩(유통대행) 관점. 솔루션-only는 *다른 출판사가 고객으로 들어올 때* 필요 → M3 멀티테넌트와 함께? 아니면 당장 설계?
2. **자체출간 vs 유통대행 구분** — 스토린랩 자체출간작과 유통대행작을 구분할지(정산 구조 다름). 책↔출판사 마스터에 계약유형 컬럼 필요할 수 있음.
3. **출판사 표기 정규화** — `마야&마루`/`마야마루출판사`, `심월`/`심월(心月)` 등 변형 통합 규칙 (작품명 정규화와 동일 접근).
