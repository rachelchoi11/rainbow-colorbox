## 6/19 — 고도화 기획·검증·통합본·연구소

### 마스터플랜·역할분담·마일스톤 수립
- 4개 작업영역 확정: A. 데이터 커버리지 확대 / B. 유통대행 모드 분리 / C. 운영화 / D. 도메인 정확도 자산화.
- 7개월 마일스톤(분석·환경 포함 개발 5개월 + 파일럿 1개월 + 수정 1개월) 구성.
- 의사결정: 실행 전 기획·구조부터 확정. 인터페이스(표준 스키마·API)를 계약으로 고정해 병렬 작업 충돌 방지.

### 신규 플랫폼 파서 추가 + PoC 검증
- 모픽·교보문고 파서를 규칙(specs)에 등록. 교보문고 원본 합계와 자동 대사 정확히 일치(1월 2,155,698원 / 4월 3,035,099원).
- 신규 월 처리 중 파일명·양식 변동 4건 발견·수정: 원스토어("원스토리"→"원스토어"), 로망띠끄(전자책/오타), 노벨피아(상세 양식), 알라딘 B2B(기관 납품 양식). 결과: 78파일 무오류, 합계 대사 실패 0.
- 검증: 기존 2·3월 파이프라인 회귀 0건(하위호환 확인).

### 미매칭 진단 — 선(先)측정으로 방향 수정
- 의사결정의 분기점: "ISBN을 작품 키로 도입하면 미매칭이 줄어들까?"를 만들기 전에 측정.
- 측정 결과 ISBN은 미매칭의 해법이 아님을 확인 — 잔여 미매칭은 예스24 등 작가·레이블 미제공 단독작이며 ISBN 자체가 없어 연결 대상이 없음. 최대 미매칭 금액은 구독 번들(원스토리 패스)로 작품이 아님.
- 시사점: ISBN은 미매칭 축소가 아니라 작품 식별 정확도의 자산. 측정으로 불필요한 개발을 사전 차단.

### 1~4월 공식 통합본 산출
- 다중 소스 파라미터화(`build_integrated.py`): 1·4월 신규 완전판 + 2·3월 원본에 교보·모픽 추가(에이블리는 중복이라 제외 → 정산액 이중 계상 방지).
- 결과: 151파일 / 431,296행 / 정산총액 11.8억원 / 검증 PASS 86·FAIL 0 / 완전매칭 99.5% / 미매칭 정산액 0.08%.

### 유통대행 모드(M2) 착수
- 측정으로 기존 가정 정정: "유통대행 책엔 출판사 정보가 없다"는 과한 가정. 실데이터에 고유 출판사 946종 존재, 스토린랩 레이블은 27행뿐(raw 출판사는 진짜 출판사명). 출판사 식별률 99.5%.
- 표준 스키마에 제공사·유통대행 여부 필드 추가, 출판사별 정산 집계 뷰 신설.

### 미매칭 보드 일괄 처리 기능
- AI 제안·외부 조회 결과에 전체선택·선택승인·전체승인 추가. 결정 이력에 복원(되돌리기)·사유 입력·일괄 복원 추가. 모든 행위 감사 추적.

### 동명이작 발견 → 매칭 오류 연구소 신설
- 작품별 화면 검토 중 "부장님 왜 이러세요"가 서로 다른 두 작품(주황연/리체북스 vs 창작집단 뻘/BOOK19)으로 병합된 것을 발견. 원인: 제목 정규화가 구두점·띄어쓰기를 제거해 충돌.
- 의사결정: 규칙을 완화(구두점 보존)하면 같은 작품의 띄어쓰기 변형이 과도하게 분리되는 더 큰 부작용 발생. 따라서 규칙 완화가 아니라 "틀릴 수 있는 경로를 관리하는 체계"를 도입.
- 매칭 오류 유형 카탈로그(E1~E10) 작성. 연구소 기능 구축: 신고 + 자동 탐지(동명이작) + 검토 워크플로우(열림→검토중→규칙반영/기각).

### 고도화 규칙 전/후 비교
- 동일 2·3월 기간 통제 비교: 모픽·교보 추가가 기존 플랫폼 행 572건의 매칭을 개선(작가만→완전 544, 미매칭→완전 28). 신규 플랫폼은 데이터만 늘리는 게 아니라 공유 마스터를 보강해 다른 플랫폼 결측을 메움.
- 1·4월 파일명 규칙으로 67,400행 복구(원스토어 66,962행 = 최대 플랫폼, 구 규칙이면 전량 누락될 뻔).

## 6/22 — 산출물 정리·보고서·작가 정규화

### 산출물 버전별 폴더 정리
- `05_산출물/`에 v1(초기 솔루션)·v2(고도화·연구소) 폴더 분리, 날짜 표기. 원칙: 문서(.md)는 이동(코드 미참조), 통합본(.xlsx)은 복사(코드가 생성·참조하는 원본 유지). 코드 회귀 0.

### E2 작가 정규화 강화 + 전후 비교
- 연구소가 적출한 첫 과제. "작가 2명 이상" 의심 489건 분석 결과 대부분이 동명이작이 아니라 표기 변형(필환 = 필환(筆煥), 무영 = 무영武映 등)임을 확인.
- 작가 정규화에 한자·영문 병기·구두점 통합 규칙 추가. 안전장치: 필명(이윤정(탠저린)), 공동작가(사마달, 고월), 순수 영문(Magoing)은 보존. 단위 테스트 10건 통과.
- 전후: 고유 작가 6,168 → 6,068(-100), 작가 2+명 작품 489 → 421(-68). 정산 총액·완전매칭 변동 0 — 작가 식별 키만 통합, 지급액 영향 없음. 실제 동명이작 96건은 그대로 유지.

### 종합보고서 작성
- v1 → v2 변경 전수 + 연구소 중심으로 구성. 7개월 마일스톤 포함.

## 6/23 — 보고서 마감·웹앱 안정화·시연 준비

### 보고서 PDF화 및 정제
- 종합보고서·작업보고서·미팅 설명자료·확인 요청서를 전문 문서 PDF로 산출(HTML → Chrome 변환). 표지에 HIVE MIND 로고, 작성자 연락처 삽입.
- 톤 정제: 이모티콘 제거, 서술형(~했다) → 개조식(~함), 구어체·AI투 표현 정리. 마일스톤을 월별로 세분화. 산출물 목록에서 내부 문서(설계노트·확인요청서) 제외.

### 웹앱 성능 최적화
- 미매칭 탭·승인이 38초 걸리던 문제 해결. 원인 둘: ① 미매칭 후보 제안(suggest)이 매번 전체 작품 풀을 순회 ② 승인마다 43만 행 전체 재매칭.
- 해결: ① 첫 글자·base 색인으로 후보 제한(17초 → 0.3초) ② 별칭은 원천 데이터 불변이라 변경된 작품만 증분 재계산(8초 → 0.02초). 전체 재매칭과 결과 동일 검증. 일괄 승인 38초 → 2.2초.
- 샘플 로드(load_sample): deepcopy(불필요하게 깊음) → 얕은 복사 + 매칭 결과 캐시. 5.5초 → 1.7초.

### 연구소·미매칭 UX 보강
- 오매칭 정의 명시(미매칭과 구분 — 못 찾은 것이 아니라 잘못 합쳐진 것). 원본 내역 보기(표준화 전 제목·작가·출판사·시트·출처). AI 제안 근거 보기(대상 작품 원본 + 유사 작품 근거 + 출처). 신고함 선택/전체 반영. 결정 히스토리 결정/복원 탭 분리.
- 연구소 정합성: 신고함에 등록·기각하면 자동 탐지 목록에서 제외(중복 방지).

### 버그 수정
- 알라딘 외부 조회 0건: `aladin_search`에 리다이렉트 추적(-L)과 https 누락으로 301을 안 따라가 빈 응답. 수정 후 후보 12건 정상.
- 신고함 저장 무반응: id 문자열 매칭 어긋남 → 버튼에서 카드를 직접 탐색하는 방식으로 변경.
- 복원 후 AI 제안 미복귀: 복원 함수가 미매칭 보드를 갱신하지 않음 → 갱신 추가.
- 연구소 → 미매칭 전환 시 무한 로딩: 비동기 렌더 경쟁 → 현재 탭 확인 + try/catch 방어.

### 정산 요약 수치 명확화
- 완전매칭 99.5% + 미매칭 0.06%가 합 100이 아닌 것처럼 보이던 문제 → 중간값 "작가만 0.44%(레이블만 없음)" 표시 추가. 완전 99.5 + 작가만 0.44 + 미매칭 0.06 = 100.

### 대외 문서 정리 및 공유
- 의사결정: 역할 분담이 아직 명확하지 않아 대외 보고서에서 강수아 이사 언급 제거(내부 기획 문서에는 유지).
- 의사결정: 미팅이 내일(6/24)이라 Railway 재배포(prod 리스크·시간)보다 로컬 시연 선택. 보고서는 회의 전날 원칙대로 디스코드에 선공유.
- 디스코드에 종합보고서 PDF 공유 완료.
