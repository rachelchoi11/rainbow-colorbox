1. 개요

정산 솔루션을 정산 데이터 분석 도구에서 출판사 단위로 운영되는 멀티테넌트 서비스 계층으로 전환하는 작업을 진행.

전환의 핵심은 데이터 구조의 분리. 배포본은 정산 데이터를 중심으로 화면이 구성되어, 출판사·유통사·계약 정보가 정산 데이터에서 파생되는 형태. 개발본은 출판사를 하나의 고객 단위(테넌트)로 정의하고, 출판사·계약·유통사 정보를 정산 데이터와 분리된 영속 데이터(마스터)로 관리. 정산은 그 마스터 위에 얹히는 구조로 확장.

도메인 정확성은 유지. 모든 변경은 기존 정산 결과에 영향을 주지 않도록 read-only 조회 계층으로 구현. 431,296행·완전매칭 99.50%·원본 대사 검증 86건 전수 통과가 전 과정에서 불변.

2. 추진 배경

배포본은 유통사 31곳의 상이한 정산서를 작가별 정산 근거가 자동 산출되는 표준 데이터로 변환하는 목표를 달성한 검증된 도구. 이를 실제 서비스로 운영하는 다음 단계를 위해 세 가지 영역을 확장.

  • 영속 마스터 도입. 출판사·유통사·계약을 정산 데이터와 분리해 상시 관리할 수 있도록 마스터 데이터 계층 신설.
  • 고객(출판사) 단위 도입. 출판사를 독립된 관리 대상(테넌트)으로 정의하고, 화면과 데이터를 그 단위로 구성.
  • 계약 계층 도입. 계약(배분율·선인세·지급처)을 추가하여 정산액에서 작가별 지급 예정액까지 산출.

이를 위해 출판사를 테넌트로 정의하고, 마스터 데이터 계층과 역할 기반 화면을 도입하는 서비스화 1단계 진행.

3. 아키텍처

시스템을 도메인 엔진과 서비스 계층으로 분리. 엔진은 계약·테넌트를 알지 못하는 순수 계산 계층으로 유지하고, 서비스 계층이 그 위에서 마스터와 워크플로우를 담당.

[ 엔진 (core) ] 순수·무상태 파싱 · 표준화 · 매칭 · 정산 산출 · 연구소 탐지 ▲ 함수 계약 (파일→레코드, 데이터→집계, 데이터+파라미터→정산) │ 현재: 라이브러리 호출 · 향후: 필요 시 HTTP 분리 [ 서비스 (service) ] 마스터·워크플로우 테넌트(출판사) · 계약 · 유통사 · 역할 · (후속: 인증·격리·확정)

정산 산출 흐름

정산은 두 단계로 구성. 엔진은 유통사가 제공한 정산액(실측 94%가 파일 제공값)을 기준으로 사용하며, 정가·수량 기반의 인세 재계산은 수행하지 않음.

1단계 (유통사 → 출판사): 정산액 = 유통사 정산서 제공값
2단계 (출판사 → 작가): 지급액 = 정산액 × 계약 배분율 − 선인세 상계 − 원천징수

4. 구축 내용

4.1 출판사(테넌트) 영속 마스터

출판사를 정산 데이터와 분리된 영속 데이터로 관리. 정산서 업로드 없이 출판사 등록·수정 가능. 정산 데이터가 있을 때는 출판사별 정산 수치를 조인해 표시하되, 조인은 전 행을 보존하는 방식으로 처리하여 정산 총액이 변하지 않도록 구현. 귀속·미귀속·라벨 미상의 합계가 정산 총액과 정확히 일치하도록 대사(11.97억원 = 귀속 + 미귀속 + 라벨 미상).

4.2 역할 기반 화면

운영자(하이브마인드)와 출판사(고객)의 화면을 역할로 분리. 운영자는 출판사 관리·전체 정산·엔진·연구소를, 출판사는 자기 데이터로 한정된 정산·계약·유통사를 조회. 출판사 화면은 선택한 테넌트 범위로 자동 한정.

4.3 계약 마스터 및 작가 지급액

출판사별 계약 마스터 신설. 권리자(작가)·역할·작품 범위·배분율·선인세(MG)·지급처·원천징수율을 관리. 계약을 정산 데이터에 적용해 작가별 예상 지급액 산출. 예시: 정산액 1.04억원 × 배분율 70% − 원천징수 3.3% = 지급액 약 7,034만원.

4.4 유통사 마스터

출판사별 유통사 마스터 신설. 각 출판사가 거래하는 유통사와 확정 정산율·수집 방식·거래 상태를 관리. 유통사 정산서 양식(파서)을 다루는 운영자의 전역 설정과는 구분되는, 출판사 단위의 거래 관계 관리.

4.5 계약서 첨부

계약 등록·수정 시 계약서 이미지·PDF를 최대 3개까지 첨부. 파일은 테넌트·계약 단위 경로로 격리 저장하며, 경로 탐색 접근을 차단.

4.6 연구소 흐름 일원화

매칭 오류 검토 체계(연구소)에서 자동 탐지와 신고 처리를 하나의 흐름으로 통합. 규칙 반영 또는 기각으로 처리한 의심 사례는 자동 탐지 목록에서 제외되어, 처리할수록 목록이 줄며 진행 상황이 드러나도록 개선. 진행 중(열림·검토중)인 사례는 계속 노출.

5. 출판사·테넌트 구조

하이브마인드 (마스터 · 운영자) ├─ 출판사 테넌트 관리 (등록 · 구독 · 상태 · 유통대행 여부) ├─ 전체 정산 현황 · 엔진 · 연구소 · 유통사 설정(전역 파서 스펙) │ ├─ 출판사 A (테넌트) ── 조인 라벨 │ ├─ 유통사 관리 (거래 유통사 · 정산율 · 수집 상태) │ ├─ 정산서 투입 → 표준화 · 매칭 → 정산 결과 │ ├─ 계약 (권리자 배분율 · 선인세 · 지급처 · 계약서 첨부) → 작가 지급액 │ └─ (후속) 작가 포털 · 명세서 · 확정 / 공개 └─ 출판사 B (테넌트) ── A와 완전 분리

원칙은 테넌트를 출판사 단위로 정의하고 출판사 간 데이터를 통합하지 않는 것. 유통사·작가·계약은 각 출판사에 종속되며, 동일 작가가 여러 출판사와 계약하더라도 별개로 관리.
