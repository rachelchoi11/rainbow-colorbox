# 정산 솔루션 배포 가이드 (담당자 외부 접속용)

실제 정산 데이터를 다루므로 **로그인 보호 + 신뢰 호스팅** 전제로 배포합니다.

## 0. 준비된 것
- 로그인 게이트 (비밀번호 1개, 세션 12시간)
- Dockerfile / requirements.txt / .gitignore (키·데이터 제외)
- 시크릿은 코드가 아니라 **환경변수**로 주입

## 1. 환경변수 (호스팅 대시보드에 설정)
| 변수 | 값 | 설명 |
|---|---|---|
| `APP_PASSWORD` | (담당자와 공유할 접속 비밀번호) | **반드시 설정**. 미설정 시 인증 없이 열림 |
| `SESSION_SECRET` | 임의 32자 (예: `openssl rand -hex 16`) | 세션 쿠키 서명 |
| `ALADIN_KEY` | ttb 키 | 알라딘 작가 보강용 (선택) |

## 2. 배포 (Railway 예시 — 가장 간단)
1. https://railway.app 가입 (GitHub 연동)
2. 이 `webapp` 폴더를 GitHub 비공개 저장소로 push
   - ⚠️ `.gitignore`가 `data/aladin_key.txt`·실데이터·캐시를 제외함 (확인)
3. Railway → New Project → Deploy from GitHub repo → 이 저장소 선택
4. Variables 탭에서 위 환경변수 입력
5. 자동 빌드(Dockerfile 감지) → 배포 → 생성된 URL 담당자에게 전달 (+ 비밀번호)

(Render도 동일: New → Web Service → Docker → 환경변수 설정)

## 3. 데이터 (중요)
- 배포본에 **26년 2·3월 데이터(스냅샷)가 번들**됩니다 (`data/sample/records.json.gz`, 2.4MB).
  로그인 후 "26년 2·3월 샘플로 둘러보기"를 누르면 **즉시 채워진 화면**(정산액 513,213,972원 등)이 보입니다 — 로컬과 동일.
- ⚠️ **실데이터가 포함되므로**: ① 저장소는 반드시 **비공개(private)**, ② 접속은 **로그인 필수**(APP_PASSWORD 설정), ③ 담당자에게만 URL·비번 공유.
- 담당자가 새 월 정산서를 직접 **업로드**해 테스트하는 것도 가능(세션 메모리, 재시작 시 사라짐).
- 데이터를 빼고 빈 상태로 배포하려면 `data/sample/`를 `.dockerignore`에 추가하면 됩니다.

## 4. 운영 메모
- 비밀번호 변경: `APP_PASSWORD` env 수정 후 재배포
- 세션은 메모리 — 재시작 시 업로드 데이터 사라짐(피드백용으로 충분)
- 다중 사용자/영구 저장이 필요해지면 DB·인증 고도화 (계약 단계)
