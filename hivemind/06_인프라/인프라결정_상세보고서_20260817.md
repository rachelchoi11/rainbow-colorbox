## 1. 스택 (언어 · 프레임워크)
- **현재:** FastAPI(Python) 백엔드 + 바닐라 JS 프론트 + pandas 데이터 파이프라인. 라이브·매일 진화.
- **이유:** 강수아가 Kotlin+Vert.x / Next.js 제안 → 유지 vs 재작성 판단 필요.
- **권장:** Python 유지. 이 규모(B2B·동시접속 수백 이하)에선 성능이 병목이 아니고, 핵심 자산인 정산서 28종 파서·40만 행 처리는 pandas가 최적.
- **선택안**
  - 👍 Python 유지 — 작동 중·개발 빠름·파이프라인 최적 / 👎 원시 서버 성능 낮음(이 규모엔 무의미)
  - 👍 Kotlin+Vert.x — 초고성능·고동시성 / 👎 전면 재작성·개발 느림·파이프라인 재구현 리스크
  - 👍 Next.js(+Node) — JS팀 개발 빠름·프론트 강력 / 👎 백엔드·데이터처리 재작성, Python보다 데이터 불리

## 2. 호스팅
- **현재:** Railway(PaaS, 관리형).
- **이유:** 정식 운영 안정성·리전·비용 관점 확정 필요.
- **권장:** Railway 유지. 단 6번(리전) 필요성 먼저 확인 — 서울 필수면 재검토.
- **선택안**
  - 👍 Railway/Render/Fly(PaaS) — 관리 쉬움·자동배포·빠른 셋업 / 👎 세밀 제어·리전 제한, 대규모 시 비용
  - 👍 AWS/GCP(클라우드) — 완전 제어·서울 리전·확장성 / 👎 운영 부담 큼(강수아 시간)·셋업 복잡

## 3. 데이터베이스
- **현재:** SQLite(파일, 볼륨). 단일 서버 전제.
- **이유:** 다중 인스턴스·외부 연동·표준 백업 필요.
- **권장:** 정식 오픈 전 관리형 Postgres 이전(db.py가 추상화돼 있어 저비용 이전).
- **선택안**
  - 👍 SQLite 유지 — 단순·무비용 / 👎 단일 서버 묶임·외부 연결 불가·동시 쓰기 제약
  - 👍 관리형 Postgres(Railway/Supabase/RDS) — 표준·확장·자동 백업·외부 연동 / 👎 접속정보 관리·소액 비용·이전 작업

- **이유:** 신뢰·브랜딩.
- **권장:** app.hive-mind.kr (기존 이메일 도메인 서브도메인 재사용).
- **선택안**
  - 👍 서브도메인 재사용 — 무료·브랜드 일관 / 👎 (거의 없음)
  - 👍 신규 도메인 — 독립 브랜드 / 👎 추가 비용·브랜드 분산

## 5. 이메일 서비스
- **현재:** 없음(초대 링크 수동 전달).
- **이유:** 초대·비밀번호 재설정·알림 자동화 — 온보딩 필수 채널.
- **권장:** Postmark(도달률·연동 최고) 또는 SendGrid(무료 티어).
- **선택안**

  - 👍 SendGrid — 무료 티어·범용 / 👎 설정 다소 복잡
  - 👍 AWS SES — 최저 비용 / 👎 설정 복잡·초기 샌드박스 해제 필요

## 6. 리전 (서버 · DB 위치)
- **현재:** Railway 기본 리전(해외일 수 있음).
- **이유:** 한국 사용자 응답 속도·데이터 소재(개인정보 국내 보관 관점).
- **권장:** 서울/근접. ⚠️ PaaS가 서울 미지원이면 2번(호스팅) 재검토(AWS 서울) 사유.
- **선택안**

  - 👍 서울 리전 — 빠름·규제 안전 / 👎 호스팅 선택 제약(서울 지원처로 한정)

## 7. 환경 구성
- **현재:** prod 하나(dev는 로컬에서만).
- **이유:** 위험 없는 테스트 → 배포 흐름.
- **권장:** dev(스테이징) + prod 2단계.
- **선택안**
  - 👍 prod만 — 단순 / 👎 실서비스에서 바로 터짐
  - 👍 dev + prod — 안전 / 👎 소액 비용·관리
  - 👍 preview까지 — 완전 격리 / 👎 지금은 과함

## 8. ★ 정산 데이터 영속 (가장 중요)
- **현재:** 업로드한 정산 데이터가 메모리 세션에만 존재 → 재배포·재시작 시 소멸. 계약사가 로그인해도 운영자가 다시 안 올리면 빈 화면.
- **이유:** 실서비스는 상시 조회돼야 함. 지금 구조면 매번 재업로드 필요 = 서비스 불가.
- **권장:** 표준화 결과를 테넌트·월 단위로 영속.
- **선택안**
  - 👍 DB(Postgres) 정규화 저장 — 쿼리·집계 유리 / 👎 40만+행 설계·부하 고려
  - 👍 오브젝트 스토리지(파케이/JSON) — 대용량 저렴·단순 / 👎 세밀 쿼리 불리(집계는 로드 후)
  - 👍 하이브리드(요약=DB, 원천행=스토리지) — 균형 / 👎 구현 복잡
