## 안건 ③ 향후 개발 방향 · 일정 협의

### 아키텍처 방향 — 모듈 분리 + API 경계 (핵심 논의)
- **정산솔루션(엔진+연구소) = 계산·판정 권위**: 파싱·표준화·매칭·정산 산출·오매칭 검증(무거운 도메인 연산). PM·도메인 담당
- **서비스영역 = 마스터·운영·워크플로우**: 출판사/작가/계약 CRUD, 정산율 계약, 사용자·권한, 승인·발행. 운영화 담당(강수아)
- "정산" = 서비스가 계약·마스터를 소유 → 솔루션에 파라미터로 산출 요청 → **확정 스냅샷(CalcSnapshot)** 수신·저장
- **"무거워짐" 리스크 방어**:
  1. 호출은 **스냅샷·배치**로 (현재 엔진 in-memory 43만행 → 매 클릭 실시간 호출 금지)
  2. **API 계약 고정**(변경은 합의 필수)
  3. **데이터 소유권 단일화**(계약=서비스만 / 정산결과=솔루션만)
  4. **솔루션 무상태화**(계약을 모르고 "정산율 X% 적용" 파라미터만 수신)
  - 위험 신호 = 서비스가 산식·매칭을 복제하거나, 솔루션이 계약·권한 상태를 알기 시작할 때 → 경계 붕괴
- **첫 합의 지점**: 오늘 넣은 유통사 관리의 "정산율 확정·수집상태"는 서비스 계층(마스터) 성격 → 서비스 분리 시 소유권을 서비스로 이관, 솔루션은 파라미터 수신. 이 API 계약을 먼저 합의
