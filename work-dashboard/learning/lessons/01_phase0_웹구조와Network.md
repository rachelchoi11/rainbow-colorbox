## 1. 웹은 "식당"이다 (3층 구조)

| 층 | 비유 | 하는 일 |
|---|---|---|
| 🧑‍💻 브라우저 | 손님(홀) | 내가 보는 화면. 주문 넣고 음식 받음 |
| 🍳 서버 | 주방 | 두뇌. "이 사람 맞아? 뭘 줄까?" 판단 |
| 📦 DB | 창고 | 데이터 보관(회원·비밀번호·게시글 등) |

**로그인 클릭 시**: 손님(브라우저)이 "이 아이디/비번 맞아요?" **주문(요청)** → 주방(서버)이 창고(DB) 확인 → "맞아요, 출입증 여기요" **음식(응답)**.

---

## 2. 요청과 응답 — F12 Network

- 버튼을 누르면 브라우저가 서버에 **요청(request)** 을 보내고, 서버가 **응답(response)** 을 돌려준다.
- **F12 → Network 탭** 에서 이 왕복을 전부 볼 수 있다.
- 👉 핵심: **개발자는 화면이 아니라 여기(데이터)를 본다.** (안연주 로그인 버그도 이걸로 해결했음)

---

## 3. login / me / Status 숫자

- **`login`**: 로그인 주문. **`Status 200` = 성공**, **`401` = "너 누군지 확인 안 됨"**(비번 틀림 또는 미로그인). 둘 다 정상 신호.
- **`me`**: "그래서 **나 누구야?**" 묻는 주문. 서버가 이름·권한을 알려줌.

| Status | 뜻 |
|---|---|
| 200 | 성공 |
| 401 | 인증 안 됨(누군지 확인 불가) |
| 404 | 그 주소 없음 |
| 500 | 서버 내부 오류 |

---

## 4. 내 "신분증" = JSON 데이터

`me` 응답을 **Preview** 로 보면 내 정보가 **JSON**으로 나온다. JSON = **"이름표: 값"** 쌍의 모음(데이터의 만국공통어).

오늘 본 admin의 신분증 해석:

| 이름표 | 값(예) | 뜻 |
|---|---|---|
| `loginId` | admin | 로그인 아이디 |
| `name` | 시스템관리자 | 화면 "안녕하세요, OOO님"의 출처 |
| `departmentName` | 경영지원실 | 소속 부서 |
| `roles` | ROLE_USER, ROLE_ADMIN | **권한** → 보이는 메뉴를 결정 |
| `consentedAt` | 2026-06-27… | 개인정보 동의 시각(있으면 동의 모달 안 뜸) |
| `iat` / `exp` | 숫자 | 출입증 발급/만료(8시간 뒤 자동 로그아웃 근거) |

**아하 2개**
- `roles` → 안연주는 `ROLE_USER`만 있어 메뉴가 달랐다.
- `consentedAt` → 안연주는 `null`이라 첫 로그인 때 동의 모달이 떴다.

## 5. 로그인 흐름 다이어그램 (W1 산출물)

```
[브라우저(손님)]              [서버(주방)]            [DB(창고)]
     |                           |                       |
 ①로그인 클릭 ──login──▶         |                       |
     |                    ②아이디/비번 확인 ──조회──▶      |
     |                           |  ◀──"맞음"────────────|
     |  ◀──200 + 출입증(쿠키)─────|                       |
     |                           |                       |
 ③나 누구? ───me───────▶         |                       |
     |  ◀──내 정보(JSON)──────────|                       |
     |                           |
 ④화면에 "안녕하세요, 시스템관리자님" 표시
```

## ❓ 내가 한 질문들 (Q&A)

**Q1. login Status가 200이면?**
→ "주문 성공" = 로그인됨. `401`은 "누군지 확인 안 됨"(비번 틀림/미로그인). 둘 다 정상 신호이고, 숫자를 **읽을 줄 아는 것**이 중요.

**Q2. `me`가 왜 두 번 나와? 로그인할 때랑 대시보드 띄울 때?**
→ **맞음! 정확한 관찰.** 두 `me`는 서로 다른 화면이 각자 물은 것:
- **1번째 me** = 로그인 화면이 "혹시 **이미 로그인**돼 있나?" 확인
- **2번째 me** = 대시보드가 "이 사람 **이름·권한** 뭐지?" 확인(화면 표시·메뉴 권한용)
- 코드도 두 군데서 부른다: `login/page.tsx`(1번째), `use-current-user.ts`(2번째). 며칠 전 고친 1줄 버그가 바로 **1번째 me** 를 읽던 부분.

**보너스 — Network 목록 읽는 법**
- **위 = 먼저 일어난 일** (시간순).
- `?_rsc=…` = Next.js가 화면을 새로고침 없이 바꿀 때 쓰는 "페이지 조각 요청".
- `notifications`가 여러 번 = 알림을 주기적으로 다시 확인(실시간처럼).
- 화면 하나 뜨는 데도 서버에 **여러 번 주문**이 나간다. 개발자는 "느린/실패(빨강) 주문"을 여기서 찾는다.
