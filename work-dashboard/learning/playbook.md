## A. 절대 주의 — 하기 전에 멈추는 명령들

이런 건 실행 전에 "이거 되돌릴 수 있나?"를 먼저 묻는다. 되돌릴 수 없으면 백업·확인 후.

| 위험 행동 | 왜 위험 | 대신 |
|---|---|---|
| `git push --force` | 남의/내 커밋을 덮어 날림 | 초보 땐 금지. 꼭 필요하면 `--force-with-lease` + 확인 |
| `git reset --hard` | 작업 미저장분 소멸 | 먼저 `git stash`로 대피 |
| `rm -rf <경로>` | 폴더 통째 삭제, 복구 어려움 | 경로 두 번 확인, prod에선 거의 안 씀 |
| prod `DROP TABLE` / `DELETE` (WHERE 없이) | 데이터 영구 유실 | 백업 먼저, WHERE 꼭, 로컬서 리허설 |
| prod `docker compose down` | 서비스 중단 | 정말 필요한지, 영향 범위 확인 |
| `.env`/키를 commit·채팅 노출 | 비밀 영구 유출 | `.gitignore` 확인, 노출 시 즉시 키 교체 |
| 잘못된 브랜치에서 작업 | 엉뚱한 곳에 반영 | 시작 전 `git status` |

**황금률**: ① 실서버(prod)에선 항상 한 박자 멈춤 ② 되돌릴 방법을 먼저 확보 ③ 모르면 실행 말고 물어보기.

## B. 디버깅 방법론 — 문제 났을 때 7단계 (오늘 우리가 쓴 절차)

감으로 고치지 말고 절차로. 오늘 "안연주 로그인 안 됨"을 정확히 이렇게 풀었다.

1. **증상 정의**: 정확히 뭐가 안 되나? "로그인 후 로그인 화면에서 깜박임 + 콘솔 404." (모호하면 못 고친다.)
2. **재현**: 같은 상황을 내가 만들 수 있나? (못 재현하면 추측만 남음. 오늘 admin/yeonju로 직접 재현.)
3. **격리 (어디까지 정상인가)**: 정상과 고장의 경계를 좁힌다. 오늘: login API=200✅, /me=200✅, 권한=allowed✅ → 서버는 정상, 문제는 클라이언트/캐시.
4. **가설**: "옛 빌드 캐시 404 + 비번 혼선" 같은 구체적 추정.
5. **검증**: 가설을 테스트. (깨끗한 브라우저=404 없음, 비번 2개 직접 시도 → 1개만 200.)
6. **수정**: 근본 원인만 손댄다(증상 덧칠 금지). 오늘: 비번 원복 + 자동리다이렉트 1줄 버그 수정.
7. **재검증**: 고친 뒤 다시 재현 시도 → 안 나면 끝. 회귀(다른 데 안 깨졌나) 확인.

> **철칙**: 근본 원인 없이는 고치지 않는다. "재부팅하니 됐어요"는 해결이 아니라 미룸.

**격리 도구(웹앱)**: F12 **Network**(어떤 요청이 빨간가) → **Console**(에러 메시지) → 서버 **로그** → DB 직접 조회. 위에서 아래로 좁혀간다.

## C. 증상별 플레이북 (증상 → 흔한 원인 → 해결)

### C1. 로그인/세션
- **로그인 후 다시 로그인 화면(깜박임)**: ①세션/쿠키 미설정 ②옛 빌드 캐시로 JS 404 ③비번 오입력. → Network에서 login/me 상태코드 확인, 하드리프레시, 비번 검증.
- **"admin인데 다른 사람으로 보임"**: 같은 브라우저에서 다른 계정 로그인 → 쿠키 덮어씀(**브라우저당 출입증 1개**). → 다시 로그인 or 시크릿창 분리. *서버 버그 아님.*
- **/api/auth/me 401**: 로그인 안 된 상태에선 **정상**(로그인 페이지가 항상 체크함). 비번 틀림 신호 아님.
- **"비번이 다르다"**: 최근 비번 리셋이 옛 비번을 덮었을 수 있음. 현재 먹히는 값 직접 확인.

### C2. 404 / 캐시
- **배포 후 화면 깨짐·404·깜박임**: 브라우저가 **옛 빌드의 JS 청크**를 부름(`_next/static/...`). → 하드리프레시(Cmd/Ctrl+Shift+R) / 시크릿창. 깨끗한 브라우저에서 404 없으면 캐시 확정.
- **API가 404**: 그 endpoint가 그 배포본에 없음(미배포) or 경로 오타. → prod에 해당 기능 배포됐는지(엔드포인트 200/404) 확인.

### C3. 빌드 / 타입 에러
- **`npm run build`/`dev` 빨간 에러**: **맨 위 메시지부터** 읽기(아래는 파생). 타입 에러면 파일·줄번호가 찍힘 → 그 줄.
- **"Cannot connect to MySQL/Redis"**: Docker 안 켜짐 or .env 주소 틀림. → `docker compose up -d` 먼저.

### C4. DB / 마이그레이션
- **신기능이 prod에서만 500**: prod DB에 새 테이블/컬럼 없음. → 마이그레이션 적용(배포에 DB 동기화 포함, 시안 규칙 `--skip-db` 금지).
- **"column/table does not exist"**: 스키마 ↔ 실제 DB 불일치. → 로컬 `db:push`/마이그레이션 재확인. *prod 변경 전 백업.*

### C5. 배포 / 서버
- **`deploy.sh` SSH 거부(Permission denied publickey)**: 이 컴퓨터에 인가된 키 없음. → 키페어 생성→공개키 서버 등록, or 담당자(강수아) 통해.
- **Docker 데몬 안 뜸**: Docker Desktop 켜기.
- **배포 후 사이트 다운**: 서버 로그 확인, 디스크 가득인지, 컨테이너 상태(`docker ps`). 안 되면 **롤백**(이전 이미지로).

### C6. 환경변수 / 시크릿
- **"JWT_SECRET is not set" / 인증 전부 실패**: env 누락. → .env 확인, prod는 주입값 확인.
- **prod 기본 시크릿 그대로**: 보안 위험. 실제값으로 교체.

### C7. Git
- **merge conflict**: 같은 줄 다른 수정. 무서운 거 아님 → 충돌 표시(`<<<<`) 사이에서 택1, 정리 후 커밋.
- **"내 변경 사라짐"**: 대개 안 사라짐. `git reflog`로 복구.
- **엉뚱한 브랜치에 커밋**: `git log`로 확인 후 cherry-pick으로 옮기기(고급, 도움받기).

## D. 안전 습관 (사고를 미리 줄이는 7가지)

1. **로컬에서 먼저.** prod는 마지막. 모든 실험은 내 노트북에서.
2. **작게 자주 커밋.** 한 번에 한 가지. 되돌리기 쉬움.
3. **브랜치로 작업.** main/prod 직접 X.
4. **변경 전 백업.** 특히 DB·prod.
5. **바꾼 건 즉시 확인.** 화면·콘솔·테스트.
6. **되돌릴 길 먼저.** 롤백·stash·reflog를 안전망으로.
7. **모르면 멈추고 물어보기.** 특히 prod·보안·삭제. (나쁜 작업 > 안 한 작업)

## E. 잘 막혔을 때 — 도움 요청하는 법

좋은 질문이 빨리 풀린다. 이렇게 공유:
1. **하려던 것** (목표)
2. **한 행동** (명령/클릭 그대로)
3. **기대 vs 실제** (무엇이 날 줄 알았는데 뭐가 났나)
4. **에러 전문** (스크린샷보다 **텍스트 복붙**, 맨 윗줄 포함)
5. **이미 시도한 것**
6. **환경** (로컬? prod? 어느 브랜치?)

→ 나(클로드)한테도 이 형식으로 주면, 오늘처럼 격리→가설→검증으로 같이 푼다.
