## 2. 우리가 이미 운영 중인 것 [사실 — 오늘 시연 가능]

레미 PoC가 필요로 하는 것 중 **이미 살아 있는 것**:

| 자산 | 상태 | PoC에서의 역할 |
|---|---|---|
| **보호자 앱 (실버톡톡)** | **실서비스 — VIP 보호자 실사용 중** | 실증 성과를 **보호자까지 전달하는 유일한 채널.** 신규 구축 불요 |
| **병원용 그룹웨어** | 25개 화면 개발 완료 (오늘 시연) | 병동별 실시간 현황·알림 이력·수면 리포트·센서 장비·알림 규칙 |
| **파트너 CMS** | 운영 중 | 환자·보호자·병실 마스터 관리 |
| **환자 명단 연동** | **가동 중** | VIP EMR(**브레인** = 헥톤프로젝트)에서 환자·병동·병실·입퇴원 수신 |
| **VIP요양병원 관계** | 운영 파트너 | **PoC 수요처가 이미 확보된 상태** |
| **전자결재 모듈** | 개발 완료 | 낙상 알림 → **사고보고서 기안 자동 연계** (오늘 시연 하이라이트) |

> **→ 핵심**: PoC의 병목은 보통 **"현장을 어디서 구하나 / 보호자에게 어떻게 전달하나"**인데, **그 두 개가 이미 해결되어 있다.**

## 4. 우리가 먼저 말씀드리는 것 — 조사로 확인한 3가지

> 조사 3건 완료: IoT 모니터링 시장·기술 / 의료기기 인증 인허가 / 요양병원 EMR 연동.
> **법령 원문·지침서 전문·1차 출처 직접 추출 기반.** 상세 자료 동봉.

### 4-1. ⚠️ 「낙상 감소」를 실증 지표로 잡으면 실패한다 [사실 — 대규모 RCT]

| 연구 | 규모 | 결과 |
|---|---|---|
| Shorr et al. | **27,672명** | 침대이탈 알람 → **낙상률 유의미한 감소 없음** |
| REFINE | 1,839명 | 동일 |
| **Cochrane 리뷰** | 메타분석 | **"알람 단독으로는 낙상을 줄이지 못한다"** |

**→ 지표를 「낙상률 감소」로 잡으면, 기술이 잘 작동해도 실증은 실패로 기록된다.**

**우리 제안 — 실제로 움직이고 증명 가능한 지표:**

| 지표 | 왜 이것인가 |
|---|---|
| **발견 지연 시간** (사건 → 인지) | 알람이 실제로 바꾸는 것. **여기서 이긴다** |
| **조치 이력 완결성** | 인증평가·사고 대응의 실물 근거 |
| **알림 응답률 / 미확인 에스컬레이션** | 워크플로우가 도는지 |
| **야간 라운딩 효율** | 인력난 = 사업의 원래 문제의식 |
| **보호자 문의 감소** | 보호자 앱 채널 보유 = 우리만 잴 수 있음 |

> **→ 낙상은 「줄이는 것」이 아니라 「놓치지 않는 것」으로 포지셔닝한다.** 이게 근거 있는 유일한 주장이다.

### 4-2. ⚠️ 의료기기 인증 — 받는 쪽이 손해다 [사실 — 법령·고시 원문]

**결론: 웰니스(비의료기기) 트랙 유지를 권고한다.**

| | 2등급을 따면 얻는 것 |
|---|---|
| 요양병원 수가 | ❌ **일당정액수가라 별도 수가 없음** |
| 인증평가 가점 | ❌ **해당 지표가 부존재** |
| 복지용구 등재 | ❌ **허가증이 요건이 아님** (고시 전문에 "허가증" 0건) |
| 정부사업 요구 | ❌ 복지부 응급안전안심 규격서 219p에 **"의료기기" 0회** |

**비용은 40배(300~450만 → 수천만~1.5억), 기간은 10배.**

**⚠️ 다만 경계선이 「질병명」이 아니라 「위급상황 탐지」에 있다** — 2026.2.12 개정 웰니스 판단기준(지침서-0091-03) 원문:
> 위해도 판단요소: **"심정지, 사망 등 위급한 상황을 탐지하는지 여부"**
> 고위해도 예시: **"수면 시 무호흡 등의 측정 기능이 있는 수면평가장치"**

**→ 제품 문구·기능 정의를 양사가 맞춰야 한다.** 우리는 이미 화면 라벨 전체를 **관측 사실 진술**로 교체했다 (`호흡 저하` → `호흡수 기준 미만`).

**✅ 제안: 「의료기기 해당 여부 검토」 공동 신청** — **무료·10일 회신**, 식약처 ☎043-719-3758. **마케팅 문구 확정 전에** 사용목적 2~3안으로 등급 민감도를 확인한다.

**➕ 기회: 복지용구 「낙상알림시스템」 급여 신설** (고시 시행 **2026.1.20**, 배회감지기와 동렬). **1호 등재 기회** — 단 재가급여라 요양병원 입원환자와는 별개 채널.

### 4-3. ⚠️ 최대 쟁점 — 보호자 앱에 무엇을 보여줄 것인가

> **실시간 바이탈과 미확인 낙상 알림을 보호자에게 그대로 주면,
> 클레임은 병원이 아니라 「우리 화면」으로 온다.**

- 보호자는 **24시간 지켜보지 않는다.** 그런데 우리 앱에 떴다는 사실은 남는다
- **오탐 30%를 전제해야 한다** (§ IoT 자료 6.2 — 벤더 "정확도 95%"와 실환경은 다르다). 오탐이 보호자에게 직행하면 **신뢰가 먼저 죽는다**
- **→ 병원 내부용(실시간·원시)과 보호자용(가공·요약·사후)을 분리한다.** VIP와도 선합의 필요

## 5. 범위 확정을 위해 필요한 것

**레미 쪽 (오늘 확인)** — 상세 26문항은 동봉 자료 §4

| | 질문 | 왜 범위가 갈리나 |
|---|---|---|
| 1 | **고정형 사양** — 레이더인가, 대역(60/70㎓), 출력 항목 | 호흡·심박·수면단계가 안 나오면 **B의 절반이 화면에 띄울 값이 없다** |
| 2 | **낙상 판정 주체** — 레미 엣지인가, 우리 서버인가 | **A·C의 범위와 책임 소재가 여기서 갈린다** |
| 3 | **전송 방식·주기**, 과거 데이터 조회 가능 여부 | 푸시/폴링에 따라 A 재설계. 과거 API 없으면 **우리가 저장** → 인프라 요건 발생 |
| 4 | **나스콜 드라이 콘택트로만 붙는가** | ⚠️ 그렇다면 **상세 데이터가 안 온다** — 접점 신호(있음/없음)뿐. **B·E의 전제가 무너진다** |
| 5 | **카메라·마이크 탑재 여부** | 탑재 시 **개인정보 난이도 급상승** — 범위·일정에 직결 |
| 6 | 보유 인증 (KC·전자파·의료기기 여부) | §4-2 트랙 정합 |

**우리 쪽 (확인 완료 / 진행 중)**

- ✅ VIP EMR = 브레인, 환자명단 엑셀 연동 가동 중
- 🔲 **VIP와 보호자 앱 노출 범위 합의** ← §4-3, PoC 설계 전 필수
- 🔲 개인정보 위수탁 구조 (우리는 수탁자) · **국내 리전 요건** — 전자의무기록 고시상 **예외 없음**
