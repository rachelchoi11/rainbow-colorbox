# 챗봇 상담예약 설정 기능 명세

작성일: 2026-05-20
대상: 파트너 어드민 > 운영 > 챗봇 상담예약

## 1. 배경 및 목적

현재 파트너 어드민의 "챗봇 상담예약" 페이지는 사용자(보호자)가 신청한 상담 예약 목록만 조회/관리할 수 있다. 그러나 파트너(요양병원 등)가 **상담 가능한 시간/요일/날짜를 직접 설정**할 수 있는 기능이 없어, 챗봇에서는 모든 날짜·시간이 예약 가능한 것처럼 노출되고 있다.

본 기능은 파트너가 챗봇 상담예약의 **운영 정책(가능/불가능 시간)**을 설정할 수 있도록 하고, 챗봇 측 상담 예약 모달(`상담 예약하기`)이 해당 정책에 따라 예약 가능 시간만 노출하고, 정책에 어긋난 예약 시도는 차단되도록 한다.

> ⚠️ 현재 챗봇 예약 모달은 사용자가 날짜·시간·이름·전화번호 등을 **모두 입력하고 `예약하기` 버튼을 눌러야** "주말은 예약할 수 없습니다." 같은 사후 안내가 노출된다. 이는 잘못된 UX이며, 본 명세에서는 **예약 불가한 날짜·시간은 애초에 선택조차 되지 않도록** UI 단계에서 차단한다 (§ 5 참조). 사후 에러 안내 영역은 제거(또는 서버 검증 실패 등 예외 케이스 전용)로 한다.

## 2. 기능 요구사항

### 2.1 상담 불가능 시간(요일/날짜) 지정

파트너 어드민 > 챗봇 상담예약 페이지에 **"예약 설정"** 영역(또는 별도 탭/모달)을 추가하여 다음을 설정할 수 있다.

| 항목 | 형식 | 설명 |
|------|------|------|
| 주말 제외 | 토글(ON/OFF) | ON이면 토요일·일요일 전체 예약 불가 |
| 공휴일 제외 | 토글(ON/OFF) | ON이면 대한민국 법정 공휴일 전체 예약 불가 |
| 개별 비활성화 날짜 | 날짜 다중 선택 | 캘린더에서 특정 날짜를 선택해 예약 불가 처리 (휴진일, 행사일 등) |

- 세 항목은 **독립적으로 동작**하며, 하나라도 해당되면 예약 불가.
- 개별 비활성화 날짜는 추가/삭제가 자유로워야 하며, 과거 날짜는 자동 정리(또는 비표시) 권장.

### 2.2 상담 예약 가능 시간 설정 (공통)

파트너 단위로 **기본 상담 가능 시간대**를 지정한다.

- 시작 시각 / 종료 시각 (예: 09:00 ~ 18:00)
- 시간 단위 슬롯(권장: 30분 단위)으로 분할되어 챗봇 측 시간 선택 드롭다운에 노출
- 점심시간 등 **하루 중 일부 휴식 시간대**도 제외할 수 있어야 함 (예: 12:00 ~ 13:00 제외)

> 현재 챗봇 모달의 "원하시는 상담시간" 드롭다운(시작/종료)이 이 설정값에서 생성되어야 함.

### 2.3 특정 날짜의 예약 가능 시간 오버라이드

- 파트너가 특정 날짜를 선택해 **그 날짜에만 적용되는 별도의 가능 시간**을 지정할 수 있다.
- 해당 날짜는 **공통 설정(2.2)을 무시**하고 오버라이드 설정만 적용된다.
- 활용 예: "토요일이지만 5/30은 특별 진료, 14:00 ~ 17:00만 가능"
- 우선순위: **개별 비활성화(2.1) > 날짜별 오버라이드(2.3) > 공통 가능 시간(2.2)**
  - 즉, 같은 날짜가 2.1과 2.3에 동시 등록되면 2.1(불가)이 이김.

## 3. 우선순위 정리 (한눈에)

특정 날짜 `D`, 시간 `T`에 대한 예약 가능 여부 판정:

1. `D`가 **개별 비활성화 날짜**에 포함 → **불가**
2. `D`가 **주말 제외 ON + 토/일** → **불가**
3. `D`가 **공휴일 제외 ON + 공휴일** → **불가**
4. `D`에 **날짜별 오버라이드 시간**이 설정됨 → 그 시간대 안에 `T`가 있으면 **가능**, 아니면 **불가**
5. 위에 모두 해당 없음 → **공통 가능 시간**에 `T`가 있으면 **가능**, 아니면 **불가**

## 4. UI 제안 (파트너 어드민)

### 4.1 진입점
- 챗봇 상담예약 페이지 우상단에 `예약 설정` 버튼 추가 → 클릭 시 설정 패널/모달 열림.
- 또는 좌측 사이드바 "챗봇 상담예약" 하위에 `예약 설정` 메뉴 신설.

### 4.2 설정 화면 섹션 구성
1. **요일/공휴일 정책**
   - [토글] 주말(토·일) 제외
   - [토글] 공휴일 제외
2. **공통 상담 가능 시간**
   - 시작 시각 / 종료 시각 드롭다운
   - 점심시간 등 제외 시간대 추가/삭제 (Row 형태로 다건 등록 가능)
   - 슬롯 단위: 30분 (고정 또는 선택)
3. **개별 비활성화 날짜**
   - 캘린더에서 선택, 칩(chip) 형태로 목록 표시, X로 제거
4. **날짜별 시간 오버라이드**
   - 캘린더에서 날짜 선택 → 해당 날짜의 가능 시간대(시작~종료, 다중 구간 가능) 입력
   - 목록 형태로 등록된 오버라이드 표시 (날짜 / 시간대 / 수정 / 삭제)
5. **저장 / 취소 버튼**

## 5. 챗봇 측 동작 (예약 모달)

기본 원칙: **불가능한 옵션은 사용자가 선택조차 할 수 없게 한다.** 사후 에러 안내("주말은 예약할 수 없습니다." 같은 빨간 박스)는 노출하지 않는다.

- 모달 진입 시 파트너의 예약 설정을 먼저 조회한 뒤 캘린더/드롭다운을 렌더링한다.

### 5.1 예약날짜 (캘린더)
- 정책상 불가능한 날짜는 **`disabled` 상태**로 표시한다 (회색, 클릭 불가, 키보드 포커스도 잡히지 않음).
  - 주말 제외 ON → 토·일 비활성
  - 공휴일 제외 ON → 공휴일 비활성
  - 개별 비활성화 날짜 → 비활성
  - 과거 날짜 → 비활성
  - 가능 시간이 0건인 날짜(오버라이드 빈 배열 등) → 비활성
- 비활성 사유 안내 문구는 캘린더 상단에 정적으로 한 줄 표기 정도만 허용 (예: "휴진일 및 주말은 예약이 불가합니다."). 선택 시 팝업/토스트는 띄우지 않는다.

### 5.2 원하시는 상담시간 (드롭다운)
- 드롭다운에는 **선택 가능한 슬롯만 노출**한다 (불가 슬롯은 `disabled`가 아니라 **목록에서 제거**).
  - 선택된 날짜의 적용 정책(오버라이드 > 공통)에 따라 슬롯 목록을 동적 생성
  - 점심시간 등 제외 시간대 → 목록에서 제거
  - 이미 예약된 슬롯 → 목록에서 제거
  - 당일 예약인 경우 현재 시각 이전 슬롯 → 목록에서 제거
- 종료 시각 드롭다운은 선택된 시작 시각에 따라 가능한 종료 슬롯만 노출.
- 날짜를 바꾸면 시간 드롭다운은 즉시 재계산 (이전 선택값이 새 정책에서 불가하면 자동 초기화).

### 5.3 `예약하기` 버튼
- 가능 슬롯이 없는 날짜를 어떻게든 선택했거나 폼이 미완성인 경우 버튼 자체를 **비활성**으로 둔다.
- 사후 빨간 안내 박스("주말은 예약할 수 없습니다." 등) 제거.

### 5.4 서버 검증
- 클라이언트 우회 가능성에 대비해, `예약하기` 호출 시 서버에서도 § 3 우선순위 규칙으로 재검증한다. 서버 검증 실패는 일반 오류 토스트로만 처리(정상 경로에서는 절대 발생하지 않음).

## 6. 데이터 모델 (제안)

```
ChatbotReservationPolicy (파트너당 1건)
├─ partnerId
├─ excludeWeekend: boolean
├─ excludeHoliday: boolean
├─ defaultStart: "HH:mm"
├─ defaultEnd: "HH:mm"
├─ slotMinutes: number (기본 30)
├─ defaultBreaks: [{ start: "HH:mm", end: "HH:mm" }]  // 점심 등
├─ disabledDates: ["YYYY-MM-DD", ...]                  // 개별 비활성화
└─ dateOverrides: [
     {
       date: "YYYY-MM-DD",
       ranges: [{ start: "HH:mm", end: "HH:mm" }]      // 다중 구간 허용
     },
     ...
   ]
```

- 공휴일 판정은 별도 라이브러리 또는 연간 공휴일 테이블 사용 (대한민국 기준).
- 시간대(timezone) 명시: 모든 시각은 **Asia/Seoul** 기준으로 저장·표시.

## 7. API (제안)

| Method | Path | 설명 |
|--------|------|------|
| GET    | `/partners/{partnerId}/chatbot-reservation/policy` | 예약 설정 조회 |
| PUT    | `/partners/{partnerId}/chatbot-reservation/policy` | 예약 설정 저장 |
| GET    | `/partners/{partnerId}/chatbot-reservation/available-slots?date=YYYY-MM-DD` | 특정 날짜의 가능 슬롯 조회 (챗봇용) |

`available-slots` 응답은 § 3의 우선순위를 서버에서 적용한 최종 결과를 반환한다.

---

## 8. 엣지 케이스 & 검증 규칙

- `defaultStart < defaultEnd` 필수.
- 오버라이드 시간대도 `start < end` 및 24시 이내.
- 오버라이드 구간끼리, 점심시간끼리 **겹치면** 저장 차단 또는 경고.
- 슬롯이 시작/종료 시각으로 정확히 나누어 떨어지지 않을 때의 처리(끝단 자투리)는 30분 미만 슬롯 미생성으로 통일.
- 동일 날짜가 `disabledDates`와 `dateOverrides`에 모두 있으면 **disabled가 우선**, 저장 시 사용자에게 경고 노출.
- 과거 날짜에 대한 오버라이드/비활성화는 입력 차단(또는 저장은 허용하되 UI에서 숨김).
- 챗봇 측 슬롯 노출은 **현재 시각 이후**의 슬롯만 (당일 예약 시).
