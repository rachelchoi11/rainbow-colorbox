## 1. 그룹웨어 개발

### 1.1 경영 현황 대시보드 신설 (`/exec`)
- VIP요양병원 **실제** 「병원주요현황보고_2026년 6월.xlsx」(314병상·5병동·재원 279명) 반영.
- **KPI 4종**: 평균 재원(목표 대비) · 병상 가동률 87.9% · 당월 청구 11.6억 · **간병비 수지 −1,281만(적자)**.
- **차트**: 일별 재원·입퇴원 / 병동별 가동률(성별 빈병상 분리) / 간병비 6개월 추이 / 행위별 청구 / 수가유형·입원경로·퇴원사유.
- **재무 포함**(원장 의사결정용). **보안 이중 가드** — 원장·병원관리자 전용, 간호사 직접 URL 접근 차단(브라우저 검증).
- **홈에 경영 요약 카드** 추가(관리자 전용).

### 1.2 ★ 엑셀 실데이터 파이프라인 — "그럴듯"이 아니라 "실제 데이터 → 대시보드"
- 하드코딩이던 값을 **병원이 매달 만드는 엑셀을 올리면 그 값으로 렌더**되게 전환. **재입력 0회**.
- 파서(순수함수·헤더 검증·정합성 체크) + SheetJS + 병원별 저장. 정합성 검사가 입력 오류를 잡음 = 효율화.
- **실증**: 원본 6월 업로드 → 정합성 이상 없음·30일 차트. **변조 7월 파일(재원 300·청구 13억)** 업로드 → 헤더·KPI 즉시 갱신 = 하드코딩 아님 확인.
- 방어 로직: 일자·빈병상이 수식이라 캐시가 없는 파일도 안 깨짐.

### 1.3 IoT 센서 전원 유형(상시전원/배터리) 구분
- 현장 센서는 상시전원이 배터리형보다 흔함 → `Device.powerType` 1급 속성. 상시전원은 "배터리 부족" 상태 없음. 등록 시 구분.

### 1.4 시연 전 결함 수정 (7/15)
- 데모 기준시각(`NOW`) 7/16 전환 + 재빌드. 라벨 "이석"→"침상 이탈"(현장에선 이석증으로 읽힘).
- **생성 낙상·침상이탈 알림이 "재실 중·깊은수면"으로 뜨던 모순 제거** — 불변식이 시나리오 경로에만 걸려 있던 것을 생성 경로에도 적용. 낙상 감지 업체 앞 화면이라 치명적이었음.

## 2. 조사 — EMR 연동 대정정

- **VIP EMR = 「브레인」 = 헥톤프로젝트**(구 브레인헬스케어, 유비케어 자회사). 요양병원 1위 벤더 확정.
- **★ 「1단계 엑셀 업로드」는 이미 프로덕션이었다** — 파트너 CMS(`partner.silvertoktok.com`)에 「엑셀에서 환자추가」가 있고 브레인 엑셀을 수기 업로드 중. 조사가 "앞으로 하자"던 게 이미 하던 일. **교훈: 외부 조사보다 우리가 이미 뭘 하는지를 먼저 본다.**
- **바뀐 결론**: 협상 포지션이 강해짐(엑셀 경로는 벤더 협조 불요), 헥톤 연동 협상 우선순위 하향.
- **신규 리스크**: 주민번호 평문 수신(S-16) → 마스킹 결정 + 파싱단 폐기가 근본 해법.

## 3. 7/16 신성델타테크(레미) 미팅

- **IoT 업체 = 신성델타테크 「레미」**(AI 시니어 돌봄 로봇, 고정형 라인업 보유).
- **미팅 성격 = 용역 발주.** 당초 KIRIA AI로봇 실증 컨소시엄(VIP+신성+실버톡톡) 무산 → 신성이 **개발용역+PoC를 자체예산으로 발주**. ∴ 법인전환 이슈 종결(자체예산이라 개인사업자 수주 가능).
- 산출물: 협의자료 1장(5p, 범위 메뉴판 A~G) + IoT 상세 17p + 시연.
- ⚠️ **계약 전 필수 2건**: S-17(PoC 지표를 「낙상률 감소」로 박으면 달성 불가 — RCT 근거), S-18(기개발분과 발주 산출물 IP 분리).

## 4. ★ 플랫폼 아키텍처 설계 (`docs/platform-architecture.md`)

### 4.1 핵심 결정 — 레거시에 안 얹고 독립 플랫폼
근거: ① 레거시 개발 통제가 강수아 개발자에 묶임(현재 계약해지) ② 라이브 앱·파트너페이지 회귀 위험 ③ 현 파트너·운영 페이지 재구축 요구. → 공유 DB 금지, **API 경계(ACL)로만** 통신, 스트랭글러 패턴.

### 4.2 레거시 실제 구성 (코드·DNS 확인)
- 백엔드 = 강수아 **Kotlin/Vert.x**, **AWS 서울**. 관리자/파트너 = Next.js, AWS 서울. CDN = CloudFront. 푸시 = Firebase.
- → 신규 Supabase도 AWS 서울이면 동일 리전.

### 4.3 확정 결정
- **데이터평면 = Supabase(AWS 서울)** — 레거시 동일 리전·경험 보유. CSAP 요구 병원 나오면 그때만 NCP.
- **7월 베타 = VIP 단일 병원 내부용**(인증+DB/RLS+배포+엑셀 업로드). IoT는 8월 PoC로 분리.

### 4.4 운영/임상 평면 분리 — "우리는 이상만 본다"
- 플랫폼 운영자는 **헬스**(가동/오류/수집지연/업로드 신선도)만, 임상 접근은 break-glass 감사.
- 규제: 국내 리전 필수 + **데이터 최소화**(EMR 원본·주민번호 미저장)로 전자의무기록 관리자 판정 회피.

### 4.5 확장성
- 확장 축은 **병원 수가 아니라 IoT 쓰기 부하**. RLS 멀티테넌트는 병원 100개도 여유, 시계열 테이블만 파티션/풀러.
